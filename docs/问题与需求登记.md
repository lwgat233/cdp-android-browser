### B-26 实时统计 + "为什么没看到数据"（用户报）—— 已实现
现象：统计画得出来但**没有数据**；用户要的是**实时**（不是按天）。
真因（4 条，全在采集端）：
  ① 内置"阅读时间"插件**只在离开页面时报一次**（只挂 pagehide）→ 正在看的页面永远不进统计；
  ② 插件里 `est.zh + est.en < 60 → return`（**正文少于 60 字连计时器都不装**）→ 视频页/首页/列表页一秒钟都不记；
  ③ **内置插件不跟着构件升级**（`seedBundled` 只按名字"缺了就补"）→ 改好的 assets 到不了设备；
  ④ 统计板块只有 小时/天/月/年，**没有"实时"**这一档。
修法：
  · 插件改成**边看边报**（可见才计；每 15 秒报增量；切后台/离开补齐；删掉 60 字门槛）；
  · ScriptStore 加 `srcHash`/`codeHash` 双哈希：用户没改过就随构件升级，改过就**不动**；
  · 统计加「实时（现在）」并设为默认：摘要＝正在读 X（+Y）· 今天 A（前台 B / 后台 C，N 条）· 连续使用 D · 最后更新；
    每 5 秒自刷（只在统计板块可见时跑）+ 最近 10 条数据表（存在本机，刷新不丢）；
  · 今天的合计口径统一成"前台+后台"（消掉"今天 28 秒（前台 29 秒）"那种对不上）。
验收：`tools/verify_live_stats.py` **18/18**（不离开页面就能看到记录出现并在涨；自动刷新；重载后数据还在）。
踩坑记录：拿"同一个小时桶"去比前台/后台会读到**真实网页**实时上报的数（桶里不只我造的那条）→ 一律按 url 取回自己造的那条来断言。

  ③ 界面里塞了大段说明文字（属于源码注释的东西跑到 UI 上）；④ 步骤行挂了个 "⋯ 操作" 键。
- 修法：① 等待类改**按秒填**（3 / 2.5 / "3秒" 都能认，`secToMs` 统一解析），认不出来就弹「参数不对」提示；
  ② 加完立刻重画列表（不等轮询）；③ 删掉界面里的说明段（注释只留源码）；④ 步骤行只留 ▲▼，
  "改这一步 / 只执行 / 上移下移 / 合并 / 删掉" 全部收进"点这一行弹出的小窗"；⑤ 信息行不再有 ⋯ 提示符。
- 证据：`tools/verify_step_add.py` **15/15**（只测这一块）：加 2.5 秒 → 队列 2500ms 且列表立刻可见；
  "3秒" → 3000ms；"abc" → 弹「参数不对」且队列不多条；步骤行按键 = ['▲','▼']；
  点行 → 小窗有 3 对信息 + ['✎ 改这一步','▶ 只执行这一步','✕ 删掉这一步']；改 2.5→7 秒 → 7000ms；`.more-cue` 数量 = 0。

## B-82（用户 2026-09-22）"过期时间和 httponly 都是一个无效值" —— 实测已定因，未修
- 现象（用户原话）：「为什么你得到的过期时间和 httponly 都是一个无效值呢」
- 实测（未改代码，实验记录 `evidence/47-cookie属性实验（落盘时延与CDP）.txt`）：
  ① **库里的那份滞后**：清空后打开测试页，3 秒读库该域行数 **0**（Chromium 批量提交）；

- 状态：**已修**（2026-09-22）。后端 `CookieDb.attrs()` 先 `flush()` + merge 里等一拍重读（≤3×200ms）+ 加 `expiresMs` + 缺行时挂 `attrMissing`；
