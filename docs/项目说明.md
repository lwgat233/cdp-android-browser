# CDP — 手机上的可编程浏览器（录制 / 回放 / 用户脚本 / 对外控制口 / 浏览模式 / 代理 / 嗅探 / Cookie）

**这是什么**：一个安卓 App。它自己是个轻量浏览器（WebView 内核，像 Via 那样有地址栏+搜索），
在此之上做了四件正经事：

1. **能跑用户脚本**（油猴语法子集）：从网址导入、粘贴手写、或 adb 推文件后扫描导入目录；
2. **能录制/回放操作**：把你在网页上的点击记成脚本，重点是那些「不是 `<a>`、点不动」的按键
   ——记录时同时记**位置锚点**（距底部/距顶部多少像素、纵向比例）和 **DOM 指纹**（标签/文字/结构路径/属性），
   回放时指纹优先、指纹失效就退回位置，用**真实触摸事件**点下去；
3. **能等、能分岔**：脚本里可以插入「等视频播完 / 等元素出现 / 等文字出现 / 等 URL 变化 / 等 N 秒」，
   还可以写「如果出现 X 就点它，否则不点」这类条件分支 —— 这是"看完一章再点下一章"的关键；
   每次回放都累计**运行次数与每步触发次数**；
4. **能下载**：网页里的下载链接（含长按菜单的「下载链接」）、控制台的「下载」页签、
   HTTP 接口三条入口汇到同一条**应用内下载** —— 自己拉、自己存到 App 私有目录，
   **不交给系统下载器**、不弹系统通知、不申请存储权限；进度与结果写进日志，记录重启后还在；
   另有 `/api/downloads/get` 让电脑侧脚本把下好的文件取回去；
5. **对外有两个接口**：debug 版 WebView 自带的标准 **CDP 调试端口**（电脑上驱动网页），
   以及 App 自己的**本地/局域网 HTTP 控制口**（搜索、找元素、点、录制、回放、脚本管理、
   等待条件、历史书签、下载，30 余个接口）。

另外：地址栏点一下**全选**（直接打字替换，回车搜索/打开）、带**历史**与**书签**，
☰ 打开的是**弹在它正下方**的下拉菜单；控制台打开时顶栏那排键依然可用。

**控制台长什么样（本轮改版）**：抽屉是**两级**的 —— 7 个归类集合 ▸ 每个集合下的栏目，顶上带"找功能 / 栏目"搜索：

```
浏览          页面与元素 · 窗口 · 页面工具
自动化        录制与回放 · 脚本 · 插件（阅读时间 / 屏幕录制）· 终端与 ffmpeg
隐私与拦截    Cookie · 密码库 · 拦截与名单 · 安全与隐身
网络与媒体    网络 · 资源嗅探 · 下载
记录与归档    历史 · 书签 · 一键导出
接口与隔离    控制口 · 给 AI / 别的软件 · 配置空间
设置与系统    设置 · 省电与后台 · 日志 · 介绍与登记表
```

这不是"手写一排按钮"，而是由功能登记表推导出来的：`assets/ui/registry.js` 里逐个功能登记
（id / 名称 / 归类 / 栏目 / 板块 / 载体 / 稳定标识 / 状态），抽屉由它生成、板块按它挂载、
启动时做一次自检（重名 / 没归属 / 登记了但页面上没有 / 页面上有但没登记）。一共 45 个功能、45 个板块。
界面里「介绍 ▸ 功能登记表」点一下就跑到自检结果；`window.__cdpRegistry()` 是它的程序入口。

包名 `dev.cdp`，minSdk 26 / targetSdk 34。

## 一、为什么这么设计（针对的实际问题）

「学习通那类页面上的下一章按钮」有四个特征，决定了实现方式：

| 现象 | 这里的做法 |
|---|---|
| 不是 `<a>`、也不是 `<button>`，就是个 `<div>`，且只挂 `pointerup` 之类的处理器 | 回放时注入**真实触摸事件**（原生 `MotionEvent` 注入到 WebView），浏览器认定 `isTrusted=true`，`pointerdown→pointerup→click` 齐全；JS 合成只作兜底 |
| 位置随滚动/视口变化 | 记录时把点击点同时换算成：视口坐标、**距底部 px**、**距顶部 px**、**纵向比例**、文档滚动位置；回放时视口高度变了就按比例还原 |
| 元素随时可能改 id/文字（框架重渲染） | 定位是**五级策略链**：id → 结构路径 → 属性 → 文字 → 位置锚点（`elementFromPoint`），每步都做可见性/文字校验，全部失败才算失败 |
| 真实手指都点不到（被浮层盖住） | 定位后先做**可点击性诊断**（中心点命中谁、被谁盖住、可点祖先在哪），并如实报告失败原因，不假装成功 |

## 二、怎么用

1. 顶栏输入网址或搜索词 → 回车（引擎默认必应，可在控制台换）。
2. 右上 `☰` 是**下拉菜单**：开始/停止监听、打开控制台、历史、书签、脚本、接口。
   控制台有七个页签，右上 `✕` 真的能关掉它：
   - **页面**：状态、找元素（选择器/文字）、诊断、点击（选择器/文字/坐标/距底部像素）、视频状态与"播完了吗"
   - **监听**：开始监听 →（关掉控制台）在页面上点你要点的按键 → 停止并保存；
     **录制过程中可随时"插入一步"**（等 N 秒 / 等视频播完 / 等元素出现 / 播放视频 / 点元素 / 条件点击）；
     也可以粘贴 JSON 导入一份录制脚本；回放时显示**每步触发次数与累计运行次数**
   - **脚本**：列表/删除、粘贴保存、从网址导入、扫描导入目录
   - **历史**：打开过的页面，点条目直接跳；**书签**：收藏/取消收藏当前页、打开、删除
   - **下载**：填地址就能下（存 App 私有目录、不弹系统通知），列表显示大小/进度/状态，可删除
   - **接口**：启动/停止 HTTP 控制口、显示 CDP 调试端口与接口清单
   - **日志**：App 日志与页面事件
3. 回放结果会给每一步的明细：用的哪个定位策略、注入点坐标、注入前后页面点击计数、
   是不是被浏览器当成真实点击（`isTrusted`）；等待步骤报"实测等了多久、轮询几次"；
   条件步骤报"走了哪个分支"；失败给原因。

## 三、三个通道（互不干扰，可同时用）

```
① 控制台界面  ──(addWebMessageListener 按 origin 开放)──┐
② 本地 HTTP   ──(ServerSocket, 默认只绑 127.0.0.1)─────┤──► Bridge（同一套 op 分发）
③ 手机本地/页面事件 ──(fetch 打虚拟源 https://cdp-event.local)┘
```

- 页面 → 原生：**不往页面里挂任何原生对象**（安全），改用 `fetch`/同步 XHR 打虚拟源，
  由 `shouldInterceptRequest` 接住（顺手做了分片，长事件自动拆包）。
- 脚本清单也用同一招：页面在 document-start 时同步取 `https://cdp-meta.local/meta`。
- 同一套 op 让「手机上点的」和「电脑上 curl 的」走同一条代码路径，验证一次等于两条都验证。

## 四、脚本格式

### 录制脚本（`.cdpscript.json`）

```json
{
  "name": "学习通-下一章", "kind": "recording", "startUrl": "https://…",
  "stats": { "runs": 2, "okRuns": 2, "lastMs": 4114, "stepFires": [2, 2, 2] },
  "steps": [
    { "t": "playVideo", "selector": "", "muted": true },
    { "t": "waitFor", "cond": { "type": "videoEnded", "selector": "" },
      "timeoutMs": 30000, "intervalMs": 300 },
    { "t": "if", "cond": { "type": "elementExists", "selector": "#nextAfterVideo" },
      "then": [{ "t": "click", "target": { "selector": "#nextAfterVideo", "id": "nextAfterVideo",
                 "tag": "div", "text": "", "attrs": {} }, "pauseAfter": 300 }],
      "else": [] }
  ]
}
```

单步字段说明：

| 字段 | 说明 |
|---|---|
| `t` | 步骤类型：`click` / `wait` / `waitFor` / `playVideo` / `if` / `goto` / `input` |
| `target` | 点击目标：`selector` / `id` / `tag` / `text` / `attrs` / `box`，外加 `anchor`（位置锚点） |
| `cond` | 条件：`{type, selector, text, value, from}`，支持 `videoEnded` `videoPlaying` `elementExists` `elementGone` `textAppears` `urlContains` `urlChanged` `always` |
| `timeoutMs` / `intervalMs` | 等条件的上限与轮询间隔（默认 20000 / 300） |
| `pauseAfter` | 这一步做完后等多久再做下一步（给页面反应时间） |
| `stats` | App 自动累计：跑了几次、成功几次、上次耗时、每步各触发了几次 |

### 油猴脚本（`.user.js`）

支持 `@name` / `@match` / `@include` / `@run-at`，GM 子集：
`GM_setValue` `GM_getValue` `GM_deleteValue` `GM_listValues` `GM_addStyle` `GM_log`
`GM_notification` `GM_openInTab` `GM_registerMenuCommand` `GM_xmlhttpRequest` `unsafeWindow`。

> 注意：脚本是**原生侧逐条注入**（`addDocumentStartJavaScript`），不是页面里 `eval` —— 
> 所以不受页面 CSP（`unsafe-eval`）限制；每个脚本一条独立注入，一个脚本语法错不会连累别人。

## 五·补充、浏览器功能（第二轮补齐：模式 / 搜索 / 隐身 / Cookie / 嗅探 / 代理）

| 功能 | 实现与边界 |
|---|---|
| **浏览模式** | `uaMode=phone`（WebView 默认 UA）/ `desktop`（桌面 Chrome UA）/ `custom`；应用后**会刷新当前页**（不刷新就等于没生效） |
| **搜索引擎** | 内置必应/百度/谷歌/搜狗/360 + 自定义模板（用 `%s` 占位）；地址栏输入不是网址时走这个模板 |
| **隐身模式** | 不记历史；**关掉那一刻**清 cookie / localStorage / 缓存，并删掉无痕期间下载的文件与记录。工具栏有 🕶 指示。Android 的 `CookieManager` 是全局的，做不到"只清无痕那部分"，界面里写明了 |
| **Cookie 查看** | 按域名查（Android 没有"列出全部 cookie"的 API，只能按域名问）；**全局列表**是拿"当前页 + 历史 + 书签"里出现过的域名逐个问出来汇总的；支持删单条、清空全部 |
| **资源嗅探** | 在 `shouldInterceptRequest` 里登记媒体请求（m3u8/mp4/webm/ts/mp3/m4a/aac/flv/mkv/mpd），**只登记不改动**；同一条地址只记一次，最多留 300 条 |
| **m3u8 下载** | 取播放列表 →（多码率主列表先取其中一路变体）→ 分片按顺序存进 `files/downloads/<名字>.hls/`，另存 `playlist.m3u8` 与 `MANIFEST.txt`（含每片地址与字节数）供对账。**不转码、不合并**；带 WebView 的 cookie，登录态的播放列表也能取 |
| **代理** | WebView 只能设 HTTP/HTTPS 代理、且没地方填账号密码，所以浏览器流量统一走 App 内的**本地中继**（`127.0.0.1` 随机端口，`ProxyController` 指向它），中继再按设置连上游：HTTP / HTTPS（连代理本身走 TLS）/ SOCKS5（带用户名密码握手）。直连白名单支持 `*` 通配。**只影响浏览器**，不是全局 VPN |

**外部协议拦截**：`bilibili://`、`market://`、`intent://` 这类深链一律不交给 WebView 加载
（WebView 不认识会跳 `chrome-error://chromewebdata/`，看着就像"点了链接就报错"）——
有 App 能接管就 `ACTION_VIEW` 唤起，没有就忽略并记日志；`intent://` 带 `S.browser_fallback_url` 时走回退地址。

## 五·补充二、这一轮按用户清单补的（拾取器 / 广告拦截 / 历史与下载导出 / 静音 / 分享）

| 功能 | 实现与边界 |
|---|---|
| **元素拾取器**（"不通过看源码来设定很难"） | 控制台或 ☰ 里点「🎯 拾取元素」→ 控制台自动收起 → 在页面上点一下 → 抓回**选择器 + 文字 + 可点击性诊断**（是 `<a>` 吗、有没有 `onclick`、`pointer-events`、光标形状、role），自动填进控制台的"找元素"框并同时填到"插入一步"的参数里。拾取期间 `pointerdown` 捕获阶段 `preventDefault + stopPropagation`，**只抓元素、不触发页面本身的行为**。原生回灌是异步的，控制台打开时还会主动问一次 `picker.last` 兜底 |
| **广告 / 统计拦截** | 域名后缀 + 关键字黑名单（内置一份保守的常见广告/统计域名），命中在 `shouldInterceptRequest` 里直接返回 **204 空响应**（不花流量）。可开关、加删规则、恢复内置、看"已拦下几个 + 最近拦下哪些"。**是基于规则的拦截**，不是智能识别，拦不到很正常 |
| **历史** | 列表**往下滑自动加载**（每页 50，上限 5000 条，带访问时间）；可**导出到系统「下载」目录**（txt / JSON，走 MediaStore，不申请存储权限）；可按**域名**删、按**日期**删（早于/晚于） |
| **下载** | 每条可**导出到系统「下载」目录**；删除分两种：**只删记录（留文件）** 与 **删记录+文件** |
| **静音此页** | Android 的 WebView 没有公开的"整页静音"接口。做法：把现有 `video/audio` 静音并暂停，挂住后续 `play` 事件与新出现的媒体节点，换页后再按一次。给"开一个窗口放视频别吵"用 |
| **分享本页** | 弹系统分享面板（标题 + 地址）；设备上没有能接的 App 时**退化成复制到剪贴板**，不会点了没反应 |

**录制与 iframe（用户报"录制对视频播放器没效果"）**：播放器常嵌在 iframe 里，顶层文档看不见子 frame 的点击。
现在把录制状态**镜像进页面 document-start 时同步取的 meta**，子 frame 自己开始记，原生侧再自攒跨 frame 的步骤；
界面与日志里会明写这步"来自 iframe/子 frame"。**边界**：真手指点 iframe 里的控件**能录到**（实测 `#innerBtn`），
但**回放到 iframe 内部做不到**——App 自己合成的触摸进不了 frame 的内容（真手指能进），日志里如实说明。

## 五·补充三、按清单第三批补的（安全 / 页内查询 / 省电 / 主页 / 外部打开确认）

| 功能 | 实现与边界 |
|---|---|
| **只有我们自己的页面能跟 App 通信**（清单第 26 条） | 页面→原生的事件通道和元信息通道现在都要带**随机口令**（每次启动换，只写在注入脚本里，且包在**闭包局部变量**里、不挂 `window`，页面自己的脚本读不到）。没口令的一律 **403** 并记日志——别的网页伪造不了事件，也拿不到脚本清单 |
| **页内查询**（第 27 条） | 控制台「页面」栏输入词→回车：命中处高亮（`<mark data-cdp-hit>`）、当前那处滚进视野，支持上一个/下一个，清除时把标签还原成纯文本（不留痕迹）。匹配过多（>800）会停手，避免卡 |
| **省电板块**（第 10 条） | 列出后台消耗项并可逐项开关：视口尺寸轮询（1.2s）、资源嗅探、广告拦截、用户脚本注入、录制中状态；另有「一键省电」（关轮询/嗅探/用户脚本 + 停录制，**广告拦截保留**——它是省流量的）。开关是**真关**：关掉嗅探后页面再请求 m3u8 也不会登记 |
| **主页改简洁**（第 20 条） | 主页只剩"搜索/地址框 + 四个入口（控制台/历史/嗅探/省电）"，入口走自有协议 `cdpctl://`；**项目介绍与版本挪进控制台的「介绍」栏目** |
| **外部打开先问用户**（第 17 条） | 点了 `bilibili://` 这类外部协议：先弹**「用哪个 App 打开？」**（列出能接管的 App，用户点哪个才开哪个；取消/返回键就什么都不做，页面留在原地）；没有 App 能接就忽略并记日志 |

## 六、已知限制（诚实版）

- 全部结论来自 **Android 14 x86_64 模拟器**，真机未测；真机上的输入注入、CSP 差异、国产 ROM 后台限制都未验证。
- **☰ 菜单不宜超过 9 项**：再多会把第一项挤出屏幕（实测点错项），新入口优先放工具栏或控制台栏目。
- **「等视频播完」只认真正的 `ended`**：不再用"快到结尾就算完"的近似（会让后续步骤提前执行）。
- **录制能录到 iframe 里的点击，但回放点不到 iframe 内部**：App 合成的触摸事件进不了子 frame 的内容
  （真手指可以），所以跨 frame 的步骤回放时按顶层页面找，可能点不到——日志与界面里会标出来。
- **广告拦截是规则黑名单**（域名后缀 + 关键字），不是智能识别；也拦不到纯 JS 拼出来或用 WebSocket 走的广告。
- **静音**是"按住"而不是系统级静音：靠注入脚本把媒体静音/暂停并拦截后续播放，个别页面可能抢在前面出声。
- **代理只作用于浏览器**（App 内中继 + WebView 代理设置），不是全局 VPN，也不支持 PAC 脚本。
- **隐身模式**退出时会清掉全部 cookie 与 localStorage（`CookieManager` 是全局的，无法只清无痕部分）。
- **m3u8 下载不转码不合并**；加密 HLS（`#EXT-X-KEY`）按原样存分片，不解密。
- 资源嗅探来自 `shouldInterceptRequest`，**看不到**纯 JS 拼出来的 blob 或 WebSocket 里的流。
- **只驱动 App 自己浏览器里的网页**。驱动别的 App 的原生界面需要无障碍服务，那是第二步，本版未做。
- 注入坐标依赖「页面视口宽度 ↔ WebView 宽度」这条换算；页面若自行缩放（`user-scalable` 之外的手势缩放）
  可能偏，回放结果里会给出注入点与页面自记几何，能看出来。
- `@run-at document-start` 的用户脚本能拿到文档开始前的时机（走原生注入），但它执行时 DOM 尚未建立。
- `GM_xmlhttpRequest` 走页面 fetch，受目标站 CORS 限制（不是原生代理）。
- 录制目前只记点击（含诊断），输入框、滚动、多标签未做；等待/条件步骤由「插入一步」加入。
- **下载**：应用内下载（不走系统下载器），支持 http/https、自动带 WebView 的 cookie；**没有**断点续传、
  暂停/继续、多任务并发控制（每个下载一个线程）；下完的文件只能通过控制口 `/api/downloads/get` 取回
  或在列表里删除，App 内没有"打开这个文件"的入口（`allowFileAccess=false`，不给本地文件开渲染口子）。
- 等待类条件目前支持 `videoEnded`/`videoPlaying`/`elementExists`/`elementGone`/`textAppears`/
  `urlContains`/`urlChanged`/固定时长；多条件与或、等网络请求结束未做。
- 条件判断是**原生侧按间隔轮询**页面（默认 300ms），不是页面事件回调 —— 好处是每步都能报
  「等了多久、轮询几次」，代价是理论上最多有 300ms 的判定延迟。
- 历史按 URL 去重（同一页刷新只留最新一条），最多 300 条；书签按 URL 去重。
- 一个 WebView 版本坑：`ScriptHandler.remove()` 会原生崩溃，因此脚本注入**只增不减**，
  靠内容哈希让旧注入失效；同一会话里反复改脚本会累积一些失效注入块（每个都是立即 return 的空转）。

## 九、本轮新增（清单继续补齐 + 界面板块登记表）

### 界面板块登记表（统一管理界面）

界面上每一块都是**有名字的 div**，写在统一的地方登记：

| 属性 | 意思 |
|---|---|
| `data-board` | 板块名（唯一，例如 `net-timeline`、`vault-main`） |
| `data-tab` | 归属栏目（例如 `security`），**一个板块只属于一个栏目** |
| `data-order` | 在这个栏目里的位置 |

启动时由 `app.js` 的 `mountBoards()` 按登记统一挂载；重名、挂到不存在的栏目都会在控制台报出来（`__cdpBoardReport()`）。控制台「介绍」栏目里有「板块登记表」按钮，能按板块名逐个列出它落在哪、第几位、当前多大。**以后报问题只需说板块名**，我就能定位到那一个 div。

### 新增功能与边界（都写在同一处，免得误解）

- **多窗口**：`/api/win`、`/api/win/new|switch|close`。诚实说明：是**共用一个 WebView 的"逻辑窗口"**——每个窗口各记 URL / 标题 / 静音状态，切换时恢复。真并行多个 WebView 在小内存机器上很容易被系统杀掉，所以选了省内存的做法。
- **二级接口**（给别的软件 / LLM 用）：`/api/help`（接口目录 + 每类怎么用）、`/api/summary`（一屏状态：页面/条数/窗口/网络）、`/api/grab`（抓当前页正文）、`/api/batch?ops=a|b|c`（一次按顺序跑多个基础接口，且禁止再套 batch）。
- **翻译**：`/api/translate`。**不假装能翻**：没配端点就明说"没配翻译端点"，离线模型（Firefox 那种 bergamot 类）需要自己放模型文件到 `files/models/`；配了端点（POST `{text,from,to}`）才真的翻。
- **助手面板插件**（`assets/scripts/assist-panel.user.js`）：右下角「✦ 助手」简洁面板，自带 Markdown 渲染（标题/加粗/斜体/列表/引用/代码/链接）。**不内置任何 AI 服务**：输入 `/页` 会把当前页正文抓出来渲染；配 `endpoint` 才把「问题 + 页面正文」发出去。
- **屏幕录制（插件形态）**：`/api/screen`。**系统不让后台替你点"开始录制"**（MediaProjection 授权是系统安全边界），接口只负责把授权弹窗叫出来，然后状态如实（`idle / awaitingConsent / recording`），文件落在 App 私有目录 `files/exports/`。
- **密码库**（清单第 4 条）：`/api/vault*`。
  - 落盘是 **AES/GCM 密文**，密钥在 Android Keystore（不在文件里、不在代码里）。
  - **看和改都要先过锁屏验证**（KeyguardManager 设备凭据，验证后 5 分钟内有效）；没解锁时列表/单条/保存一律拒绝，只回 `needUnlock=true`。
  - 设备**没设锁屏**时，按清单要求就是不能查看和修改——接口会如实说"先设锁屏"。
  - 随机密码：长度 + 大写/小写/数字/符号四类**各自可开关**（关掉的类一定不出现在结果里）。
  - 页面有登录框时弹一条「要不要保存」；点了会先要锁屏验证，密码不进日志。
  - 边界：不做"所有站点自动填充"（要用户主动点「填这一页」）；指纹/人脸只走系统凭据流程，本身不做生物识别 UI。
- **每个窗口的静音与数据屏蔽**：静音状态是**跟着窗口走**的（窗口 1 静音不影响新开的窗口）；广告/统计拦截仍是全局规则（按域名黑名单），不做逐窗口的拦截规则——这点在界面上写明。

## 十、本轮新增：伪终端与"屏蔽不渲染"

### App 内伪终端（控制台「伪终端」栏目）

- 接口：`/api/term?cmd=<命令>`；界面：输入框 + 输出区（↑↓ 翻历史）。
- 命令：`pwd / cd / ls [-l] / cat / head / tail [-n] / wc / mkdir / rm [-r] / mv / du / stat / find / grep / echo / date / df / md5 / sha256 / curl <url> [名] / net dns <主机> / net tcp <主机> <端口> / clear / help`。
- **边界（写进 help 里）**：Android 应用不能 fork/exec 系统 shell，所以这是**应用内命令解析器**，
  不是真 shell；文件操作限制在 App 私有目录（`cd ../../`、`/data/data` 一律拒绝）；不支持管道重定向与后台作业；
  **ffmpeg 未内置**（会明确回"未内置"，要用得先交叉编译进来）。

### "屏蔽不渲染"式广告处理（清单第 3 条的重点）

- 三种方式：`both`（命中回空 + 隐藏元素）、`hide`（**只隐藏不阻断**）、`block`（只回空）。
- `hide` 的意义：有些站点的 JS 会探测"广告资源是不是被拦了"，发现被拦就不给正文；
  只隐藏不阻断可以让页面照常运行，而广告位被 CSS 藏掉（注入 `#__cdp_cosmetic`，不删元素）。
- 隐藏规则是可维护的 CSS 选择器清单（内置一份保守清单：`ins.adsbygoogle`、`[id^=div-gpt-ad]`、`[class*="advert"]` 等），
  支持加/删/恢复内置，以及"推到当前页"（改完立即可见）。
- 边界：拦截规则仍是**域名/关键字黑名单**（拦不到 JS 动态拼出来的广告）；隐藏是 CSS 层，
  极端情况下页面自己会用内联 `!important` 反制。

## 十一、内置 ffmpeg（清单第 7/8 条）

- **怎么内置的**：用预编译的 **ffmpeg-kit-min 6.0-2**（LGPL 变体）作为依赖打进 APK，跑在**应用进程内**——
  不需要把二进制塞进 assets 再 exec（Android 10+ 本来也禁止从应用私有目录执行文件）。
  代价：APK 从 ~1.7MB 涨到 **~31.8MB**（两个 ABI 各约 27MB，压缩后合计）。
- **能做什么**
  - `/api/ffmpeg`：版本与能力边界（含"不能做什么"）。
  - `/api/ffmpeg/info?url=`：用 **ffprobe** 读媒体信息（容器、时长、码率、每条流的分辨率/编码）。
  - `/api/ffmpeg/remux?url=&name=`：把 m3u8/HLS（或 mp4/flv）**拉成一个 MP4**（`-c copy`，不重编码）——
    这就是"用 ffmpeg 强制下载视频"；产物落在 App 私有目录 `files/ffmpeg/`，并用 ffprobe 复核过时长/流。
  - `/api/ffmpeg/run?args=`：跑任意 ffmpeg 参数（界面上给了常用例子）。
  - 伪终端里的 `ffmpeg` 命令走的就是这一份（`ffmpeg` 不带参数会报版本与边界）。
- **边界（如实写在返回里）**：min 变体**不含 x264/x265/fdk-aac 这类 GPL 编码器** →
  能做**转封装/复制流**，**不能重编码**（要重编码得换 `ffmpeg-kit-*-gpl` 变体，体积和许可都会变，本工程没用）。
  ffmpeg-kit 官方已停止维护（归档），但制品仍可从 Maven 取到；升级/替换时注意这点。
