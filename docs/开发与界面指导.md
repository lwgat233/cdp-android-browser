## M-1 坐标录制的归属（改这块前必读）

**坐标步只由原生层记**：`MainActivity.dispatchTouchEvent`（录制中且方式是 coord 时）拿真实触摸，
`Bridge.addNativeCoordStep` 回顶层页面问 `anchorAt` 得到锚点，再作为一条 `mode:'coord'` 的步入队。

- 页面/frame 里的 agent **不记坐标步**（`cdp-agent.js` 里 coord 分支直接 return）；
  坐标模式下 Bridge 还会**丢掉页面报上来的 click 步** —— 因为跨域 frame 的镜像态会滞后，
  实测同一次点击变成两条。
- 为什么不用页面 JS：跨域 iframe / 原生视频表面 / 播放器手势，页内 pointerdown 都可能收不到
  （用户报的"点播放视频录不到"就是这个）。
- 回放匹配：坐标步**不做"像不像"校验**（`locate()` 里 `step.mode === 'coord'` 直接取锚点处最上层元素），
  语义就是"就点在这儿，不管那儿现在是什么"。元素步才需要指纹校验。
- 坐标录制**只记真实手指**：回放/脚本注入（`/api/click`、`injectTap`）产生的触摸不算 ——
  这个不需要额外标记：注入走的是 `WebView.dispatchTouchEvent`，**不经过 Activity**，所以天然不会被记。

## M0 模块边界（改界面前先读这一节）

渲染层在 `assets/ui/modules/`，依赖**单向**：`app.js（各栏目小功能）→ modules → DOM`。

- 要弹信息 → `CDPUI.Modal.open({title, fields, onSubmit, extras, options})`；
  形态只有一种：**键小字在上、值就是文本框**（`editable:false` 就是只读文本框，长相一样）；
  底部由渲染器自己给〔恢复原始值〕〔确定〕，抬头 ✕ 是不保存退出；**不要自己拼 DOM 小窗，也不要往里塞没有落点的键**。
- 要列表 → 给行塞 `data-title` / `data-fields`，行里的 `<button>` 会被 `list.js` 搬进小窗当动作；
  **不要往行面塞常驻按键**（用户的硬规矩）。
- 键值对一律交给 `CDPUI.KV`（键小字在上 / 值大字在下 / 横线）—— 自己拼会跟别处长得不一样。
- 接完自查：`__cdpModules().violations`、`__cdpModules().duplicateIds`、`__cdpRegistry().problems` **三个都空**。

**双入口口径必须一致（本轮踩的真坑）**：同一个动作有第二个入口时（☰ 菜单、快捷方式、控制口 URL），
第二个入口必须**读同一份状态、带同一份参数**。实例：控制台里选「坐标录制」，
☰ 菜单那条 `rec.start` 没带 mode → 永远退回元素录制，用户报"坐标录制没效果"。
规矩：新加入口时先问"这个入口从哪读用户的设置"，读不到就先把设置**同步到原生**（`rec.mode` 就是这么加的）。

**撞 id 是一类真坑**：`$('id')` 只拿到第一个，第二个板块就"点了没反应"或输出跑到别处。
两个板块的同名控件（比如都叫「更多 ▾」）必须给不同 id；`__cdpModules().duplicateIds` 每次验收会扫出来。

## M1 后台媒体（熄屏 / 切后台还要继续放）

- **不要自己去抢音频焦点。** WebView 里的 HTML 媒体由 Chromium 的 AudioFocusDelegate 申请焦点；
  服务里再申请一次 AUDIOFOCUS_GAIN，Chromium 判定"被抢"→ 立刻 pause（实测 paused false→true、进度停住）。
  真正让媒体在后台活下来的是：**前台服务的 mediaPlayback 类型 + partial 唤醒锁**。
- **前台服务类型要跟着模式走**：`startForeground(id, n, types)`，媒体模式用
  `FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK or FOREGROUND_SERVICE_TYPE_DATA_SYNC`；Android 14 不声明直接抛。
- **别 pause WebView**：onPause 里只调 super。一旦 `webView.onPause()` / `pauseTimers()`，媒体立刻停。
- 验收：切后台后要证明"**真的在往前走**"（媒体进度或 `timeupdate` 次数），光看 `paused=false` 不够。

## 一、界面：先扁平、再归类、再落载体

1. **功能先在后端做全**，别一边做功能一边摆按钮 —— 功能没齐就摆界面，必然反复推翻。
2. **列成扁平二维表**（id / 名称 / 归类 / 载体 / 入口 / 稳定标识 / 状态），写进 `assets/ui/registry.js`。
3. **归类**：5~7 个集合，一个功能只进一个集合；跨集合只放**跳转入口**，不复制控件。
   当前 7 个：浏览 / 自动化 / 隐私与拦截 / 网络与媒体 / 记录与归档 / 接口与隔离 / 设置与系统。
4. **按粒度选载体**：
   - 大功能 → 独立页面/面板（浏览器本体、控制台、多窗口）；
   - 中功能 → 可折叠卡片（一行摘要，点开才展开）；
   - **小功能（单条数据）→ 列表行只给摘要 + 点一下弹小窗**（动作都在窗里）；
   - 状态 → **一行文字**，不要用一排按钮表达状态。

硬规矩三条（第三条是用户踩过好几次才写进来的）：

- **R1 一个渲染入口**：清空重建，不追加节点；同一栏目只在一个地方刷新。
  实测踩过：弹窗的动作栏用 `parentNode.appendChild(bar)` 挂上、从不清理 →
  **每打开一次多一排同样的按键**（用户原话："我多次按它，小窗口按键重复多次"）。
  修法：整个弹窗"清空 + 按固定三块（抬头 / 正文 / 动作栏）重建"，点多少次都只有一份。
- **R2 列表只给摘要 + 常驻按钮 ≤3/行**（第 4 个进 `更多 ▾`）。
- **R3 信息型列表的行里不放按键**：**行 = 一条信息**，**点这一行**（或长按）→ 弹窗，
  **先把这条的字段按「字段：值」列全**，动作（下载 / 播放 / 删除 / 复制…）排在信息下面。
  列表渲染时给每行塞 `data-fields`（`[["字段","值"],…]`），没塞的按行内文字自动列字段；
  行里已有的按键由统一处理器搬进小窗（它们只是"动作的来源"）。

三条都能自检（都在页面里可查）：

```js
__cdpButtonRows()   // 每行的可见按钮（> 3 的行要收进"更多 ▾"）
__cdpRowScan()      // 每一行：有没有可见按键 / 能不能点开 / 有没有这条的信息字段
__cdpModalScan()    // 小窗：几排动作栏 / 键位文案 / 有没有重复（连点 N 次后应仍是 1 排）
```

顺手检查（浏览器里就能跑）：

```js
__cdpRegistry()        // 归属/重名/漏挂 的自检，problems 必须是 []
__cdpBoards()          // 每个板块落在哪个栏目、第几位、尺寸、有没有挂上
__cdpMissing()         // app.js 用到了但页面上没有的 id（会变成"死键"的根源）
__cdpButtonRows()      // 每行的可见按钮，> 3 的行必须收进"更多 ▾"
```

## 二、代码：三条接线规矩

1. **后端 op 先行**：能力加在 `Bridge.kt`（`<模块>.<动作>`）；要给外部用，就加 `HttpControl.kt` 路由 + `ApiCatalog.kt` 一行。
   **先在 HTTP 控制口上 curl 通**，再接界面 —— 一条链路通了，两条通道（App 内 / 电脑 curl）都通。
2. **界面接线只用 `bindMaybe(id, 'click', fn)`**，不要写 `$('id').addEventListener(...)`：
   前者在元素缺失时只记一笔（`__cdpMissing()`），后者会抛 `TypeError` 把**后面所有注册一起打断**
   ——现象是"一大片键突然都点不动"，而根因只是少了一个元素。
3. **HTML 元素先到场，再写 JS**；改 HTML/JS 的脚本要"改完立刻落盘"，别让中途异常把两件事一起丢掉。
4. 状态用文字：`拦截：已开启　广告规则 43 条 · 隐藏规则 9 条 …`、`当前：隐私与拦截 › 拦截与名单`。
   开关类：**一个键**（`开 / 关 X`）+ 一行文字状态，不要"开/关"两个键。
5. 存储与匹配器**只留一份**：例如"站点警告名单"原本是 settings 里的逗号串 + 另一套后缀匹配，
   现已并进 `AdBlock`（一个 `adblock.json`、一个 `matchWarn()`、一套 op；老的 `security.block.*` 保留为别名）。

## 三、验证：四层证据，缺一层都不算验过

| 层 | 工具 | 看什么 |
|---|---|---|
| ① 自检 | `__cdpRegistry()` / `__cdpMissing()` | 归属、重名、漏挂、缺 id（**本轮真的抓到过：替换 HTML 时吞掉两个板块**） |
| ② 真进程状态 | `node tools/cdp.mjs file --target ui/index.html --file tools/probe_ui_round.js` | 板块挂载、栏目切换、更多▾、行小窗、后端 op 往返 |
| ③ 死键扫描 | `node tools/cdp.mjs listeners --target ui/index.html --selector "button,select,input"` | `dead` 必须为 0 |
| ④ **真手指** | `python3 tools/verify_ui_round.py`（`adb shell input tap`） | 用户到底点不点得到：坐标现测，读回 DOM 状态 |

规矩：

- **合成事件只能证明逻辑通，证明不了"点得到"**。关键路径必须真手指点一次，并**读回可观测状态**
  （DOM 类名 / 面包屑文字 / section.on / 节点 bounds）——"没报错"不算通过。
- **坐标一律现测**：`uiautomator dump` 里取 `resource-id` 对应节点的 bounds 中心。
  WebView 内部元素也能这么取（无障碍树把它们暴露出来，节点带 `resource-id = 元素 id`）。
- **折叠起来的东西在无障碍树里没有大小是正常的**：断言"当前可见"要按"展开的集合"现算期望值，
  写死数字会得到假红（本轮就假红过两次）。
- **自动化要先把上一轮的残留状态归位**：抽屉是否已经打开、`更多 ▾` 是否还展开、抽屉搜索是否还带过滤。
  上一轮超时退出会留下这些状态，下一轮读到的就是"点一下反而收起"这类假红。
- 每步都加超时兜底（`subprocess timeout` + 命令侧 `timeout`），别让一次 dump 卡住拖死整轮。

## 四·五、控制口安全（改这块前必读）

控制口是这个 App 的"外部手"——它能读 cookie / 跑页面 JS / 取下载文件，所以有三条硬规矩：

1. **默认只绑 `127.0.0.1`**：局域网里的设备连不上；要局域网访问必须显式 `?lan=1`。
2. **绑了局域网就要令牌**：非本机调用必须带 `?t=<token>` 或请求头 `X-CDP-Token`；
   令牌**每次启动随机生成**（不给固定口令，重启即失效），本机调用免令牌（既有自动化不受影响）。
3. **敏感接口在局域网下默认关闭**：`vault.*` / `cookie.*` / `eval` / `downloads/get` / `settings/set` /
   `export` / `space.use` / 取令牌这类，要显式打开才放行（`/api/security/sensitive?on=1`，或界面里
   「安全与隐身 ▸ 控制口安全」的开关键）。

配套：

- **令牌只在本机取**（`GET /api/security/token`）——非本机哪怕带对了令牌也不回令牌本身，免得被"转发"；
  界面里的「看一眼令牌」走的是 App 内通道（信任边界内）。
- 回包统一带 `X-Content-Type-Options: nosniff` 与 `Referrer-Policy: no-referrer`；被拒的请求会**记数并写日志**
  （面板上能看到"被拒 N 次"，日志里能看到 remote 地址与路径）。
- 拒绝用 **HTTP 403 + 原因**，不是"200 里塞个 error"：这样外部脚本一眼能分清"没权限"和"功能坏了"。
- 控制台界面自己有 CSP（`default-src 'self'`，无 `unsafe-eval`）：页面里 `eval` 是被拒的
  （验收里就 assert 这一条），所以**别在界面 JS 里用 `eval` / `new Function`**，否则功能会被 CSP 静默拦掉。

验收：`python3 tools/verify_security.py` —— 它用"App 自己的浏览器访问 `10.0.2.15:8848`"来当
**局域网里的另一台设备**（服务端看到的来源就不是 127.0.0.1），逐条验：不带令牌 403 / 带令牌 200 /
取令牌 403 / 敏感接口默认拒、打开后放行 / 安全头齐 / 被拒计数在涨 / CSP 生效且界面照常；
**测完把状态恢复成安全态**（只绑本机 + 敏感关闭）。

## 五、资源纪律（这台宿主只有 7.8G 内存）

- **构建与模拟器不要并行**：构建前 `bash /vol1/1000/aicache/docker/emu.sh stop`，构建完再 start
  （实测：构建 + 模拟器同时跑会把可用内存压到 1.5G 以下）。
- 构建：`gradle --no-daemon --offline :app:assembleDebug -Pkotlin.compiler.execution.strategy=in-process`，
  `org.gradle.jvmargs=-Xmx1024m`，全程只有一个 JVM。
- **构建成功与否只认 gradle 退出码**：产物文件存在不能当判据（失败时旧包还在，会拿旧包去测）。
- **跑测试用 127.0.0.1 的本地靶子优先**：离线靶子（控制口自带的 HLS 页 / 音频源 / 功能测试靶）
  让结论不依赖外网，也不会因为容器 DNS 异常而假红。

## 六、媒体嗅探与音频（本轮扩的广度，改这块前先读）

- 认的扩展名：hls `m3u8` / dash `mpd` / 视频 `mp4 m4v m4s fmp4 cmfv f4v webm mkv flv` /
  音频 `mp3 m4a m4b aac flac opus ogg oga weba wav` / 字幕 `vtt srt ass`；每条带 host / 文件名 / 归类。
- **分片要合并**：同一路（同目录）的 `.ts` / `.m4s` 合并成一条「分片 ×N」——
  不合并的话一个频道几百条会把清单刷爆（实测 6 次取片合并成 1 条）。
- **两条抓取路径**：`shouldInterceptRequest`（请求层）+ `sniff.scanPage`（页面里 performance 资源 +
  `video/audio/source` 标签）。**用了 MSE（`blob:`）的站，正片直链不在请求层** —— 界面里明说这条边界，
  别当 bug 报；能抓到的是预加载的那条 mp4 与清单/分片。
- **下载要用真 http(s) 地址**：App 自己的虚拟源（`appassets` / `cdp-event.local` / `cdp-meta.local`）
  只活在 WebView 的请求回调里，外部下载器解析不了那个主机名（会 `UnknownHostException`）。
  本机测试源走 `http://127.0.0.1:8848/...`（控制口已提供离线音频源 `/api/_test/audio/sample.mp3`）。
- **HLS 音频转存**：`ffmpeg.remux` 只换容器不重编码（AAC-in-TS → m4a 可以，重编码不行），
  界面按钮上就写清楚"转存 m4a"，不要暗示成"重新编码成 MP3"。
- **清空清单后旧页面会重新登记**：还在播的页面会继续发请求 → 界面提供「只看当前页」，
  验收里也要用这个筛，别把残留当缺陷。
