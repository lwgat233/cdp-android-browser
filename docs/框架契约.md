# 框架契约（拆文件 + 局部构建 + 未接入不报错）

用户 2026-09-21 定的三条，本文把它们写成可执行的规矩：

1. **不做真插件包**（不打包成独立 JAR/Dex/文件去加载）——逻辑上解耦，物理上仍是一个 APK。
2. **可以拆成很多文件**——按能力/渲染器拆源文件，互不影响。
3. **测试时只编你动过的那部分、只跑那部分的验收**，不整包、不跑全量。
4. **没接上的部分不许报错，也不许为了编译通过去改别的地方。**

---

## 一、为什么"只打包一个文件"不能这么做，但"局部"能做到

APK 是一个整体，没法单独打一个源文件。但把它换成工程上等价、而且更快的事：

| 你想的 | 实际做法 | 耗时 |
|---|---|---|
| 只打包改动的那个文件 | **只做增量编译**（`:app:compileDebugKotlin`） | 几秒~十几秒（全量 assembleDebug ≈ 60 秒） |
| 改一行界面也要重装 | **界面文件推到设备**（`tools/devpush.sh`），控制口优先读它 | **约 2 秒**，完全不重建 |
| 每次跑一堆验收 | `tools/pick_tests.py` 按 `test_map.json` 只跑该功能的脚本 | 只跑相关的几个 |
| 发布 | `tools/fastcheck.sh --publish`（整包 + 装 + 归档） | 一天几次，不是每改一行 |

一条命令：
```
tools/fastcheck.sh app/src/main/java/dev/cdp/NetTools.kt
tools/fastcheck.sh app/src/main/assets/ui/modules/appgrid.js
tools/fastcheck.sh --feature apps
tools/fastcheck.sh --publish          # 只有要发布/要换构件哈希时才走这条
```

**覆盖层怎么证明自己生效**：控制口每次吐 `ui/` 文件都带 `X-CDP-Source: dev|apk` 头。
`dev` = 跑的是推到设备上的那份（刚改的），`apk` = 跑的是打进构件的那份。验收读这个头，
"我测的是哪一份"就不再靠猜。`/api/dev/assets` 能列出现在覆盖了哪几个文件。

---

## 二、怎么拆（拆文件，不拆构件）

- 原生：一个能力一个文件、一个顶层 object（例：`AppsStore.kt`、`PageTimer.kt`、`NetTools.kt`）。
  **不许互相直接改对方的状态**：要过 op，或者读对方的只读方法。
- 界面：`index.html`/`start.html`（装配）+ `app.js`（装载与接线）+ `modules/*.js`（渲染器）+ `registry.js`（登记表）。
  一个渲染器一个文件，一个渲染入口（清空重建），**不许第二条渲染路径**。
- 数据：一份数据只有一个权威源（SQLite 表 / 本机设置里的一个 JSON 键）。
  跨模块只允许走 op 或只读方法。

拆到什么时候算好：**加一个同类功能，只用加一个文件 + 一条登记，不改别人的文件。**

---

## 三、未接入不许报错（四条硬规矩）

"没接上"是所有松散框架最先烂掉的地方。四条：

1. **op 未知**：回 `{"ok":false,"error":"未知命令 xxx"}`，**不抛异常、不崩**（现在 Bridge 已是这个行为）。
   调用方拿到的是一句人看得懂的话，不是堆栈。
2. **数据没到 / 为空**：渲染器出**空态文案**（一句"下一步怎么做"），不是空白、不是报错。
   `state` 字段给 `loading | empty | ready | error`，渲染器按它挑显示。
3. **控件没接线**：**不摆这个键**（绝不摆一个点了没反应的键）；条件不成立就不出现。
   界面自检要能报出来"登记了没做 / 没有交互 / 没有测试"。
4. **可选依赖缺省**：模块之间的依赖必须是**可选**的（拿不到就给默认实现/空实现），
   **不允许出现"为了编译通过，得去改另一个文件"**。这条是松散结构的生死线：
   一旦拆开就必须能单独编译、单独运行、缺邻居也能跑。

## 四、信息列表的统一契约（一个渲染器吃遍所有列表）

任何模块要给界面出"一列表东西"，就照这个形状回：

```json
{"ok": true, "state": "ready",
 "columns": [{"key":"name","label":"名称"},
             {"key":"size","label":"大小","align":"end","fmt":"bytes"}],
 "rows":    [{"id":"…","name":"…","size":123}],
 "total": 1234, "hasMore": true, "nextCursor": "…",
 "actions": [{"id":"open","label":"▶ 播放","op":"player.open","args":{}}],
 "empty": "还没有下载过的文件"}
```

- **列定义 / 行数据 / 动作声明三样分开**：行面不摆按键（动作交给点行小窗）。
- `align` / `fmt` 交给渲染器统一处理（bytes / 时长 / 百分比），业务层不碰样式。
- 分页写进契约（`total` / `hasMore` / `nextCursor`）——别把十万行塞一屏。
- 判据因此固定：DOM 行数 == `rows` 数；点行小窗里的动作 == `actions`；空态文案 == `empty`。
  **验收不用一事一议。**

## 五、一个功能要交的四样（"给它什么"）

1. **接口**：op 名 + 参数 + 回包形状（机器可读；人看的那份由它生成，不许手写 → 防漂移）。
2. **数据**：表/键名 + 字段 + 迁移；一份数据只有一个权威源。
3. **界面**：控件（文字 + 调哪条 op + 参数 + 显示哪份数据 + 什么条件才出现）与载体（行/小窗/折叠/一屏）。
4. **视图**：数据 → 视图的映射（view 类型 + 字段映射 + 三态文案）。

四样齐了，主 JS 才能"不认识这个模块，也能把它画出来并让人点得动"。

## 六、效率的结论（用户问过，写在这里免得再问）

- **分层不贵，物理拆构件才贵**。同 APK 内的模块 + 声明式契约：几乎零成本，还可能更快（能内联、能裁剪）。
- 真跨边界（Binder/不同 ClassLoader）的成本：调用 0.1~1ms/次，**序列化才是大头**（上万行 JSON 编码+解析 = 几十毫秒）；
  外加类加载、冷启动、内存按 ClassLoader 增长、版本矩阵与签名。
- 红线：**一次跨边界的数据 ≤ 一屏所需**（虚拟列表 + 游标）；**渲染循环里不许跨边界**；能批就批。
- 本项目这套（WebView + 本机控制口 + 一套 op）进程内 JS→原生约 0.3~3ms，
  所以"拆文件"在这里主要是**组织成本**；真正的瓶颈永远是**过桥的数据量**与**重复渲染**。

## 七、测试版 APK 放哪儿、叫什么、带什么说明（用户 2026-09-21 定）

专门测某个功能的构件，**不放临时目录**，放项目里的固定文件夹，并且自带说明书：

```
apk/测试版/
  cdp-首页小app网格-测试-20260921-0230-01.apk        ← 文件名自带：项目名 + 功能 + 测试版本
  cdp-首页小app网格-测试-20260921-0230-01.apk.txt    ← 同一份说明书（与 APK 一一对应，哈希可核）
```

说明书（.txt）里必须写清：**项目名 / 测试版本 / 测试的功能（含功能 id）/ 打包时间 / 构件哈希 / 大小 /
APK 路径 / 源码快照位置 / 包名与入口 / 怎么装 / 怎么确认装的是这一版 / 该跑哪些验收 / 只测这个功能不跑全量**。

一条命令：
```
tools/pack_test.sh 首页小app网格 --id apps        # 打包 + 写说明 + 装到设备 + 重建端口转发
tools/pack_test.sh 樱花动漫嗅探 --no-install      # 只打包归档
```

同时会把 `{project, testVersion, feature, featureId, builtAt}` 写进 `app/src/main/assets/build-info.json`
**打进 APK 里** —— 装上去之后界面和验收都能读到"这是哪个测试版"，不用靠文件名猜。
（顺带解决登记 B-49：界面版本串以后从 build-info.json 读，不再手写死。）

## 八、改一行界面不用重建 APK（覆盖层）

```
tools/devpush.sh app/src/main/assets/ui/modules/appgrid.js   # 推到设备，约 2 秒
tools/devpush.sh --clear                                     # 撤掉，回到读 APK
```
控制口每次吐 `ui/` 文件都带 `X-CDP-Source: dev|apk`；`/api/dev/assets` 列出当前覆盖了哪些文件。
**验收前读这个头**，就能证明"测的是刚改的那份"还是"构件里的那份"。
