## 0. 每一条都适用的要求（不是可选）

### 0.1 三面验收（缺一面都不算测过）
| 面 | 要读回来的事实 | 工具 |
|---|---|---|
| API | 回包里的**数字/列表**变化（不是只看 `ok:true`） | `curl /api/...` |
| 控件 | **真手指点**那个键，点完读副作用 | `adb shell input tap`（坐标现测） |
| 渲染 | DOM：元素个数 / 计算样式 / 选区 / 文本 | `uiprobe` |

真手指点的硬规矩：先 `ui/open` 开浮层并断言 `window.innerWidth > 0`；先滚进视口并把横向归零；
点完**读副作用**，没生效**重试**（这台模拟器约 1/3 丢输入）；同名元素要**精确匹配**；异步结果要**轮询**。

### 0.2 按键怎么定（加功能前先答这几问）
1. **用户在这一屏要做什么决定？** 写不出一句人话 → 不该有键。
2. **一个键一句话**：点了会发生什么？答不上来 → 删。
3. **做完该收的键要收**：会让人"回到网页去看"的动作（播放 / 打开 / 跳转），点完要**收起面板回到网页**。
4. **常驻键 ≤ 3**；信息行的行面**不摆键**（由列表渲染器收进小窗）。
5. **条件不成立就不摆**（不是置灰、也不是弹一句"请先选"）。
6. **能长按就别加键**（文本框复制→长按选中）。
7. **入口只留一个**（其余改成跳转入口）。
8. 写完**扫死键**：每个可见键必须有落点且落点真做事。

## 1 录制脚本板块：一键清空 + 小窗删除 + 「载入步骤」要在「监听与录制」里出现

**功能**：录制脚本要能一键清空/删除；在「监听与录制」那块里也要能"把某条脚本的步骤载入进来编辑"。

| 项 | 内容 |
|---|---|
| 板块 | 自动化 ▸ 录制与回放 |
| 按键 | `#rc-clear`「清空录制脚本」（弹窗确认）；每条录制脚本行小窗里的 `✕`（删这一条）；`#rc-load`「载入到步骤列表」 |
| 判据 | ① 点清空 → `scripts.list` 里 `kind=recording` 的条数 = 0；② 点行的 ✕ → 只少那一条；③ 点「载入到步骤列表」→ `#r-steps`（监听与录制里的步骤列表）出现 N 行，且与回执里的步数一致 |
| 轻量测法 | `verify_rec_ops.py`：清空 → 造两条 → 载入 → 读 `rec.live` 步数与 `#r-steps` 行数 |
| 边界 | 清空只删 `recording`，不动用户脚本（内置/粘贴的） |
| 涉及 | `index.html`、`app.js(renderRecList)`、`Bridge.kt(rec.load)` |

### 28.1 三种状态怎么表示（用户 2026-09-22 补充，参考 Firefox 手机版）
用户原话：「还有多窗口模式我之前说了要干嘛，什么表示在后台，什么表示当前，什么表示历史下来的，参考firefox」

对齐 Firefox（Fenix）的三态，落到本项目的窗口列表上（**每行左侧一个状态标记 + 当前行高亮**，不写说明文字）：

| 状态 | 含义 | 数据来源 | 行上怎么表示 |
|---|---|---|---|
| **当前** | 正在显示的那一个 | `win.list` 里 `active=true` | 整行高亮（已有）+ 左侧**实心点** |
| **后台** | 开着但没显示，状态还保活中 | `kept=true` 且非 active | 左侧**空心点**（灰），标题正常亮度 |
| **历史下来的** | ① 被回收过的（`kept=false`，切回去要重新加载）；② **关闭过的**（能恢复） | ① `kept=false`；② 新增的"最近关闭"记录（标题+地址+关闭时间） | ① 标题**变暗** + 右侧一个"要重载"的小标记；② 单独一个小节「最近关闭」（最多 10 条，点一下恢复成窗口） |

判据（读回来的事实）：
- ① 开 3 个窗口 → 只有当前那个是实心点，其余是空心点（读 DOM 上的状态标记 + `win.list` 的 active/kept）；
- ② 开满 12 个 → 被回收的那几个行上出现"要重载"标记，且切过去之后标记消失、地址还在；
- ③ 关掉一个 → 它出现在「最近关闭」里；点它 → 重新成为窗口（`win.list` 条数 +1）；
- ④ 重启 App：窗口列表与「最近关闭」都还在。
