## 一、回放进度可见（功能 id：`rec.progress`）

### 归属与载体
- 归类集合：**自动化** ▸ 栏目 **录制与回放**（板块 `rec-main`）。
- 载体：**页面上的一份提示**（回放期间控制台是自动收起的——用户明确要求"回放要退回网页、看得见过程"，
  所以进度必须画在**页面**上）+ 已有的**页面内小点**（同一份 `dotsSet` 数据，不新造第二份真身）。
- 不新增常驻按键（`rec-main` 的按键数不变）：进度是"显示状态"，按界面铁规用**一行字 / 一个标记**表达。

### 现在的行为（真因）
- 页面里的小点渲染器**已经**支持 `state`：`current`=橙色、`done`=绿色、其它=蓝色（`cdp-agent.js` `dotsRender`）。
- 但脚本回放（`Bridge.runRecording` → `DotBus.setBusy(true)`）会让 `pushDots()` 带上 `on = dotsOn && !busy`
  → **整批隐藏**。所以回放时页面上什么都不显示，"正在执行哪一步"只能靠回放结束后看回执。
- 隐藏的原因是历史坑：小点是 `pointer-events:auto`，注入的真实触摸会打到点上 → 把这一步又点一遍（成环，B-09）。
  即"要看得见"和"别被点到"这两件事当时是**冲突**的 —— 现在有解：回放期间把页面小点设为 `pointer-events:none`。

### 要做成什么样
1. 回放期间**页面小点保持可见**，并按步推进状态：
   - 正在执行的那一步：`current`（橙）；已执行过的：`done`（绿）；还没到的：`idle`（蓝）。
2. 页面上另给一条**进度条小字**（非交互元素，`pointer-events:none`）：
   `回放 第 3/8 步 · 点「下一章」` —— 步数 + 这一步在干什么（元素文字优先，坐标步给坐标）。
3. 页面小点在回放期间一律 `pointer-events:none`（防成环）；回放结束后恢复原样（可点=自己点）。
4. 控制台/回执面同步：每步往日志里写一行（`第 3/8 步 ok=…`），开始/结束仍用现有那行覆盖式回执；
   回放结束的汇总（跑 N 次/成功 M 次）不变。

### 判据（读回来的事实，不是"看起来对"）
- 回放进行到第 i 步时，读页面 DOM：
  ① `#cdp-dot-<i>` 的 `data-state == "current"`；`#cdp-dot-<(i-1)>` 为 `"done"`；后面的为 `"idle"`；
  ② 进度文字的 `textContent` 能匹配 `第 <i>/<N> 步`；
  ③ 小点命中测试：`getComputedStyle(dot).pointerEvents == "none"`（回放期间）。
- 不成环（B-09 的回归判据）：录 3 步的脚本回放一次，3 个点的 `data-state` 都变 `done`，
  且日志里"第 k 步"每个只出现一次（不是 2×N 次）。
- 回放结束后：小点恢复可点（`pointer-events != none`），进度文字消失。

## 二、"指定页面位置为视频"（功能 id：`sniff.pick`）

### 归属与载体
- 归类集合：**网络与媒体** ▸ 栏目 **资源嗅探**（板块 `sniff-main`）。
- 按键：`sniff-main` 现在已有 3 个常驻键（刷新 / 从页面里再找一遍 / 更多 ▾）—— **加不进第 4 个**，
  所以新键放进已有的「更多 ▾」小盒里：**「指定位置为视频」**。
- 交互：按下去 → 控制台收起、页面顶部出现一行提示（"点视频所在的位置"）→ 用户点页面上一处
  → 该位置下的媒体地址进嗅探清单（条目标注来源 `手动指定`），随后照常可播放/下载。

### 为什么需要它（现状的边界）
- 自动识别靠两处：`shouldInterceptRequest` 的请求地址 + 页面里再扫一遍（`video/audio/source`、performance 资源），
  两者都**按扩展名归类**（`Sniffer.kindOf`）。解析不出的常见情形：
  · MSE/`blob:` 播放（地址不是真实资源，如 DASH/加密流）；· 地址无扩展名（`/stream?id=123`、`.php`）；
  · 跨域 iframe 里的 `<video>`（页面脚本读不到）；· 列表在 JS 里、请求被包装过。
- 现在能兜底的只有"手填地址"（`sn-url` 那行）——**用户不知道地址**时就没辙，这正是他说的痛点。

### 要做成什么样
1. 进入选取模式后，用户点页面一处 → 取该点下的元素链（`elementFromPoint` 后向上找祖先）：
   ① 元素自身/祖先或其后代里的 `<video>/<audio>/<source>`：取 `currentSrc` / `src` / 各 `<source src>`；
   ② 若命中 `<iframe>`：取 `iframe.src`，并在回执里如实说明"里面的地址要等它自己请求"；
   ③ 元素上的 `data-src` / `data-url` / `href`；
   ④ 兜底：把嗅探清单里"与该元素同一路径目录/同一 host 且最接近的媒体请求"作为候选列出（让用户挑）。
2. 候选给用户**选一条**（多条时用小窗列出来，一条一行；只有一条就直接加入）→ 写进嗅探清单，
   `from: 手动指定`、`pickedAt`（时间）、`via: 位置`（元素标签/文字，便于日后认）。
3. 加入后：行上动作与自动嗅探到的完全一致（播放 / 下载 / 投屏 / 转存），不新造第二套。
4. 失败要如实说：什么都没找到就说"这一点下没找到媒体地址"，并把该位置记录进日志（不假装成功）。

### 判据
- 造一个**故意识别不出**的测试页（`<video>` 用 `blob:`/无扩展名路径 + 跨域 iframe 一种），
  先证明自动嗅探**确实**没把它列出来（对照组，不是想当然）；
- 点「指定位置为视频」→ 真手指点视频区域 → 清单里出现该条目、`from=手动指定`、能播放（读播放器状态）；
- 什么都没找到的位置：回执必须是一句"没找到"，且清单条数不变。
