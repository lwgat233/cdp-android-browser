## 一、为什么这些结论可信（方法）

六条证据链，缺一不可：

1. **结论来自 App 自身的结果对象**，不是"看起来对了"：回放每一步都返回
   定位策略、注入点坐标、注入前后页面点击计数、是否 `isTrusted`、等待步骤的**实测等待毫秒数与轮询次数**、失败原因。
2. **页面侧独立计数**：测试页对每个控件自记触发次数与 `isTrusted`，并把收到的指针坐标与元素自身几何记下来
   （`window.H.lastGeo`），用来核对注入坐标准不准。
3. **真视频、真事件**：等待类功能的验证用的是测试页里一段**真实的 3 秒视频**（`clip.webm`，VP8），
   断言"播放真的发生了（`plays=1`）、`ended` 事件真的触发了、点击发生在它之后"，而不是手工 dispatch 一个假事件。
4. **电脑侧标准 CDP**：`adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>` 之后，
   用零依赖探针 `tools/cdp.mjs` 从 App 外部读页面与控制台 DOM（下拉菜单切栏目那条就是这么验的）——
   与 App 接口互相对照，读数必须一致。
5. **对照组成立才认结论**：例如"这个 div 用 `el.click()` 打不动"，先跑一次证明计数不变，
   再证明真实触摸能点着；否则测试页不具代表性，结论作废。
6. **反例也要过**：条件分支既验"条件成立走 then"，也验"条件不成立走 else 且 then 里的动作确实没发生"；
   目标移走后必须**如实报失败**，不许乱点。
7. **下载要拿字节说话**：下载的验证不是"日志里写了成功"，而是把下回来的文件**再取回来算 sha256**，
   与源文件逐字节比对（本次 4096 字节随机文件 → sha256 一致）；同时查系统下载服务里没有本 App 的条目
   （证明"不交给系统下载器"不是嘴上说的）。
8. **界面按键用真实手指点**：地址栏、☰、工具栏按钮、菜单项全部用 `adb shell input tap` 按**实测坐标**点，
   读回来的状态（焦点、文本、菜单项边界、录制状态）当判据 —— 不用"看起来能点"当结论。

修法要点：菜单锚到 ☰ 自己；地址栏 `setSelectAllOnFocus(true)` + 显式可聚焦 + 点一下唤起键盘；
浮层从工具栏**下面**开始（`topMargin=46dp`）；装 `DownloadListener` 并接上**应用内下载**（见下）；
`onDestroy` 里 `removeCallbacks` 撤掉轮询；下载**先写 `.part` 再改名**并校验长度（#20）。
另外把工具栏按钮的最小触摸尺寸提到 44dp（原来是 32dp 宽）。

### 下载这块的实现（按用户要求：不交给系统下载器）

`DownloadListener` / 控制台「下载」页签 / HTTP 接口 `/api/download` 三条入口汇到同一条应用内下载：
`HttpURLConnection` 自己拉（带 WebView 的 cookie）、存到 `filesDir/downloads/`、进度与状态写进
`files/downloads.json`（重启后还在）、日志里能看到进度与结果。附带一个**取回接口**
`/api/downloads/get?name=`（带 `Content-Disposition: attachment`），方便电脑侧脚本把文件拿走 ——
验收里的 sha256 比对就是用它做的。

## 五、已知限制与未覆盖

- 结论全部来自 **Android 14 x86_64 模拟器**（google_apis，无 root）；**真机未测**：
  真机上的触摸注入时序、国产 ROM 后台限制、真实 CSP 差异都未验证。
- **代理只作用于浏览器**（App 内中继 + WebView 的代理设置），不是全局 VPN；代理本身**不支持 PAC 脚本**。
- **隐身模式**在 Android 上无法做到"只清无痕那部分"：`CookieManager` 是全局的，所以退出无痕会清掉
  全部 cookie 与 localStorage（界面上写明了）。
- **m3u8 下载不做转码/合并**，存的是"播放列表 + 分片 + 清单"；要合并成一个 mp4 得在电脑上做。
  加密的 HLS（`#EXT-X-KEY`）只按原样存分片，不解密。
- 资源嗅探靠 `shouldInterceptRequest` 登记请求，**看不到**纯 JS 拼出来的 blob 或 WebSocket 里的流。
- 只驱动 **App 自己浏览器里的网页**；驱动别的 App 的原生界面需要无障碍服务，属第二轮，本版未做。
- 无头模拟器长时间连跑会自己 SIGSEGV 崩掉（宿主上是 swiftshader 的 ColorBuffer 报错，容器 Exit 139）。
  验收脚本已改成"设备不在线就明确报环境问题"，但这不是应用缺陷，重跑即可。
- 注入坐标依赖「页面视口宽度 ↔ WebView 宽度」换算；页面自行缩放时可能偏（回放结果同时给出注入点与页面自记几何）。
- `evaluateJavascript` 偶发返回 `null`（脚本没跑成），App 侧做了一次重试并如实报错，无法根除。
- 录制目前只记点击；输入框、滚动、多标签、`@run-at` 的时序细节未做。
- 等待类条件目前支持：`videoEnded` / `videoPlaying` / `elementExists` / `elementGone` / `textAppears` /
  `urlContains` / `urlChanged` / 固定时长。更复杂的组合（多条件与或、网络请求完成）未做。
- Doze 长挂、锁屏后长时间不操作的表现未测。

### 11.2 屏幕录制（Android 14）
四层坑，逐个修完才通：

| 层 | 现象 | 修法 |
| --- | --- | --- |
| 1 | 点"开始录制"后报 `Media projections require a foreground service of type FOREGROUND_SERVICE_TYPE_MEDIA_PROJECTION` | 清单加 `FOREGROUND_SERVICE_MEDIA_PROJECTION` 权限 + `ScreenService`（`foregroundServiceType="mediaProjection"`） |
| 2 | 服务被系统判 `ForegroundServiceDidNotStartInTime` 杀进程 | 通知渠道**提前**建好（放 `onStartCommand` 里现场建会拖过宽限）+ `startForeground` 放最前 + 失败就 `stopSelf` |
| 3 | 仍报同一条投影错误（`dumpsys` 里 `startForegroundCount=0`、服务日志一行都没有） | 顺序改为"**起服务并等就绪 → 取投影 → 建虚拟屏**"；等与建都放**后台线程**（主线程在收弹窗，服务回调会晚到 6 秒以外，实测差 30ms 翻车） |
| 4 | `IllegalStateException: Must register a callback before starting capture` | 建虚拟屏**前** `projection.registerCallback(...)`，停止时 `unregisterCallback` |

结果：`files/exports/screen-1789804660129.mp4` = **219,412 字节**（真 mp4，能停能存）。
说明（如实）：前台服务**必须有常驻通知**，录屏期间会出现"CDP 正在录屏"，这是系统要求、绕不过去。
