# 界面模块化（功能与运行代码解耦）

用户的要求：**功能代码要解耦、抽象成模块**（UI 渲染、小功能…各自成块），
小窗尤其要解耦 —— **给小窗渲染器发：标题、键值对、按键、以及每个按键对应的小功能**。

## 一、现在的分层

```
assets/ui/
├── registry.js          功能登记表（唯一数据源：功能 → 集合 → 栏目 → 板块）
├── transport.js         与原生通信（CDPT.call(op, args) → Promise；25s 无回包=超时）
├── modules/             ← 渲染层模块（互不依赖 UI 细节，可单独替换）
│   ├── fmt.js           小工具：mk / time / host / bytes / short / putEmpty
│   ├── kv.js            键值对排版：键小字在上、值大字在下、横线分隔；没字段时按行内文字兜底
│   ├── modal.js         小窗渲染器（唯一造小窗的地方）
│   └── list.js          列表行渲染器（行 = 一条信息，点行弹窗；行面不给按键）
└── app.js               各栏目自己的**小功能**：只做两件事 —— 取数据、把数据交给上面这些渲染器
```

依赖方向是**单向**的：`app.js → modules → (DOM)`；模块之间只有 `modal → kv → fmt`、`list → modal/kv/fmt`，
没有反向依赖，也没有模块去读 app.js 里的东西。

## 二、小窗渲染器的接口（这就是用户要的那个形态）

```js
CDPUI.Modal.show({
  title: '第 3 章',                       // 标题
  pairs: [['时间','2026-09-20 09:12'],     // 键值对（交给 kv.js 排版）
          ['地址','https://…']],
  buttons: [                               // 按键 + 每个按键对应的小功能
    { label: '下载', op: 'download.start', args: { url: u } },   // 声明式：模块帮你发出去
    { label: '复制', run: function () { … } },                    // 或直接给一个函数
    { label: '删除', danger: true, run: delIt }
  ],
  note: '可选的一行小字说明'
});
// 也兼容老签名：Modal.show(title, text, rows, actions, pairs)
```

其它接口：`Modal.close()`、`Modal.scan()`（验收入口）、`Modal.actions(title, summary, acts)`、
`Modal.actionButton(row, title, summary, acts, label)`。

**硬规矩 R1（踩过痛的那条）**：小窗只有一个渲染入口，每次都是「清空 + 按数据重建」，
**绝不 appendChild 追加节点** —— 以前动作栏只追加不清理，现象是用户说的「小窗按键重复多次」。
小窗元素带 `data-renderer="modal.js"`，自检能查出"没走渲染器"的小窗。

## 三、列表行渲染器的接口

渲染函数**只管塞数据**，长相由模块决定：

```js
const row = mk('div', 'row-item');
row.setAttribute('data-title', '第 3 章');                      // 小窗标题
row.setAttribute('data-fields', JSON.stringify([               // 小窗里的键值对
  ['时间', fmtTime(x.ts)], ['地址', x.url]
]));
// 想给这条记录留动作，就在行里放 <button>：模块会把它们**搬进小窗**当动作，行面不给按键
row.appendChild(mk('button', '', '删除'));
host.appendChild(row);
```

`List.watch()` 挂在 `document.body` 上，**新出现的行自动接管**（不用每个渲染函数各写一遍）。
行带 `data-sheeted="1"` + `data-renderer="list.js"`。

## 四、自检入口（验收读这些，不靠"看起来对"）

| 入口 | 读什么 |
|---|---|
| `__cdpModules()` | 装了哪些模块（名字@版本+接口）、行数、有多少行走了 list.js、小窗渲染者/按键排数/重复文案、**重复 id 列表**、`violations`（没走渲染器的行或小窗） |
| `__cdpRegistry()` | 功能登记表自检：漏挂/重名/归属冲突 → `problems` |
| `__cdpRowScan()` | 每行：有没有可见按键、能不能点开、有没有字段 |
| `__cdpModalScan()` | 小窗：几排动作栏、按键文案、有没有重复 |

## 五、加一个新功能时怎么落（照这个顺序）

1. 想在哪个栏目？去 `registry.js` 登记一条（id / name / coll / tab / board / order / carrier / entry）。
2. 在 `index.html` 对应栏目里加一个 `data-board="…"` 的卡片。
3. 需要列表 → 给行塞 `data-title` / `data-fields`，键值对交给 `CDPUI.KV`；
   需要弹信息 → 用 `CDPUI.Modal.open({title, fields, onSubmit, extras, options})`（`show({title,pairs,buttons})` 仍兼容）；
   值一律是文本框（可改 / `editable:false` 只读），底部〔恢复原始值〕〔确定〕由渲染器给；**不要在栏目代码里自己拼 DOM 小窗**。
4. 跑一次 `__cdpModules().violations` 和 `__cdpRegistry().problems` —— 两个都空才算接对了。

## 五·五、小点（坐标步骤的落点）走的是**原生**覆盖层，不是页面渲染

坐标步骤在屏幕上画成编号小点。这件事**不能**在页面里做：页面里画的点会被原生视频表面 /
系统弹窗盖住，而用户要的正是"在播放器那块也能看到点、也能点它"。

- 覆盖层：`CdpDotService`（无障碍，`TYPE_ACCESSIBILITY_OVERLAY`）+ `DotBus` 渲染；
  **不读界面内容**（`canRetrieveWindowContent=false`），只画点 + 收点的点击/拖动。
- 页面里那份（`agent` 的 `dotsSet`）只是兜底/给自动化读 DOM 用；两份数据都来自 `Bridge.pushDots()`。
- 回放期间覆盖层必须 `FLAG_NOT_TOUCHABLE`，否则注入的点击打在点自己身上、页面收不到。
- 编号规则：**按队列序号**，元素步也占号（不画点）→ 页面上出现 1 2 4 是正确的，不是 bug。
- 合并：记录时同处连点自动合成一个点（`reps`）；手动「和上一个点合并」——
  同处则 `reps` 相加，不同处则合成 `t=clickGroup` 的**点组**（仍然一步，按顺序各点一遍）。

## 六、这一层之外（原生侧）的分块

原生已经是"一个功能一个文件"，改哪块看名字就行：
`Sniffer.kt`（嗅探）、`AdBlock.kt`（拦截规则）、`HttpControl.kt`（控制口）、`Bridge.kt`（页面↔原生的 op 路由）、
`KeepAliveService.kt`（后台常驻/后台播放）、`MainActivity.kt`（窗口与菜单）、`ApiCatalog.kt`（接口目录）。
界面模块与原生之间**只通过 `transport.js` 的 op 名**耦合 —— 换界面不动原生，反之亦然。
