二、这一夜新发现的问题（全部已登记，按重要性排序）
────────────────────────────────────────────────────────────────
P1【最坑·新】**系统弹窗抢焦点 → 真手指全落空（整轮假红）**
   launcher 触发 ANR，弹窗 `Application Not Responding: com.google.android.apps.nexuslauncher`
   一直在 mCurrentFocus 上，BACK 按不掉 → `adb shell input tap` 全部打在弹窗上
   → 首页网格验收 9 条全红，看着像"我做的按键坏了"。
   处置：force-stop launcher + 拉回本应用 → 焦点回到 dev.cdp；
   已把"焦点在本应用吗"做成环境体检的一项（带自愈）。
P2 真手指的正确实现（我踩了两遍）
   · 必须 `adb shell input tap`（设备侧真实触摸）＋ **uiautomator 量 WebView 屏幕框** ＋ `innerWidth` 现读换算；
   · `cdp.mjs tap` 是 `Input.synthesizeTapGesture`（合成手势），**不能当"真手指"用**；
   · CSS 宽写死 393 而实际 412 → 点偏约 90px（前一天把结论带偏一整轮）。
P3 调接口前先照源码核对入口名
   `/api/settings`（只读，改了不生效）≠ `/api/settings/set`（应用并刷新）；`/api/sniff/list` 根本不存在。
P4 下载源与**控制口同端口**：流大文件时控制口被占住（/api/_test/hls/big.bin 卡在 bytes=0），
   测试自己都读不到进度 → 判"下载进度条"别用大文件，或把测试源挪到别的端口。
P5 验收脚本不要用 location.reload() 做"干净状态"（栏目/列表/筛选全丢）；
   每节开头要关掉并**清空**小窗，否则读到上一节残留的文案（假红假绿都出过）。
P6 行内动作不许"代理点击"（已修）：小窗里直接摆那个**真元素**，否则点它静默不执行。
   —— 用户反复报的"小窗里的按键都没用"就是这个根因（探针 op 日志已证明修好）。
P7 模拟器容器这一夜 **SIGSEGV 崩了 7 次**（exit=139，非 OOM，宿主内存充足）；
   崩的时机都在这类重负载之后：连续真手指点击 + 媒体播放 + 下载。
P8 **应用刚重启就立刻跑验收**会全红（控制口/转发还没就绪）—— 所以每轮先 env_health.py 再跑验收。
P9 小坑：Kotlin 字符串里嵌中文引号会编译失败（`"服务器 IP"`）→ 改用「」。
