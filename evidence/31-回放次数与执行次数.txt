一、用户要的（原话）
════════════════════════════════════════════════════════════════════

「而运行脚本应该有那个什么运行多少次的功能？运行步骤也要有运行多少次的功能。」

→ 三处都要能填次数：①「回放这条脚本」②「▶ 跑当前队列」③步骤小窗里的「▶ 只执行这一步」。

════════════════════════════════════════════════════════════════════
二、怎么做的
════════════════════════════════════════════════════════════════════

界面（assets/ui）
  · 回放那一行加一个**次数输入框** `#r-times`（默认 1，placeholder「次数」）——按用户定的规矩，
    要填的东西就是文本框，不再加解释文字。
  · 生效规则（`runTimes()`）：非法（0 / abc / 空）按 **1 次**；**1..50 夹住**；填完把生效值**写回框里**
    （免得你以为填了 0 就跑 0 次）。
  · 「回放这条脚本」「▶ 跑当前队列」都按这个次数跑；输出先给一行汇总
    「跑 3 次：成功 3 次，总耗时 1234ms」，再逐次列「第 N 次：成功/有失败（ms）」，最后是最后一次的逐步结果。
  · 步骤小窗里加一项「**跑几次**」（属于**执行参数**，不进步骤数据、不会被保存进脚本）；
    「▶ 只执行这一步」读它跑 N 次，输出「第 2 步：跑 3 次，成功 3 次」。

原生（Bridge.kt）
  · `runRecording(id, times, reply)`：最外层 `onePass(n)` 跑第 n 遍，里面还是原来的 `step(i)` 逐步执行；
    每遍之间隔 400ms；回包既有**每一次**的结果 `runs[]`（每次 ok + ms），又保留 `steps`（＝最后一次的逐步结果，兼容旧界面）；
    每遍都累计进脚本的 `stats`（runs / okRuns / stepFires），日志写「跑 N 次，成功 M 次」。
  · `rec.runOne` 支持 `times`：单步也跑 N 次，回包 `times / okTimes / ms / runs[]`（每次带 ms），
    并且**记进 `lastRun`**（"上次运行"统一能查）。
  · `times` 一律 `coerceIn(1, 50)`：手滑填 999 → 按 50 跑，不会把设备点疯。
  · 界面运行时提示（connStep）会写「第 2/3 次回放…」，跑多次时看得见进度。

顺带修掉的真缺陷
  · **HTTP 那层等主线程只等 20 秒**：`/api/replay?times=50` 这种长回放明明在跑，接口先回一句「超时」。
    改成 `call(op, args, timeoutSec)`，回放/跑队列/单步 默认 **240 秒**（可带 `waitSec=` 覆盖）。
  · 给「跑」这几种操作开了外部入口（同一套 op，脚本化与验收都读得到同步回包）：
      `GET /api/run?what=one|queue&i=&times=N`
      `GET /api/play/last`   ← 最近一次运行的完整记录（含 finishedAt）
      `GET /api/replay?script=&times=N&waitSec=`
  · 回包都带 `finishedAt`：判断「这是不是这一轮跑的」有依据（界面与验收都用它）。

三、验收（读回来的事实）
════════════════════════════════════════════════════════════════════

$ python3 tools/verify_run_times.py     → 17/17 通过
$ python3 tools/verify_replay_pick.py   → 10/10 通过（回归）
$ python3 tools/verify_modal.py         → 34/34 通过（回归）

关键几条：
  · 次数框默认 1；填 0 / abc / 空 → 框里被规范成 1，且**真跑 1 次**
  · 回放脚本 3 次（走界面按钮）：last.times=3、runs 长度 3、每次 ok 且 ms>0；脚本累计 runs 4 → 7（增加 3）
  · 「▶ 跑当前队列」2 次：last.times=2、runs 长度 2
  · 单步执行「跑几次=3」（走步骤小窗的按钮）：last.times=3、okTimes=3、总耗时 1305ms（≥3×200ms，确实跑了三遍）
  · 上限：times=999 → 实际 50 次，runs 里有 50 条记录

════════════════════════════════════════════════════════════════════
四、边界（别当已做）
════════════════════════════════════════════════════════════════════

  · 跑多次时**中间某一次失败不会中止后面的次数**（按用户要求"跑 N 次"就是 N 次；每次的成败都记在 runs[] 里，
    汇总行给"成功 M 次"）。要"失败就停"的话再提，那是个开关。
  · 上限 50 是硬编码（`coerceIn(1, 50)`）；要改上限说一声。
  · 「跑几次」不写进脚本（它是执行参数），所以回放脚本本身不带次数；次数只在界面上/接口调用时给。
