本轮（界面归类 + 嗅探广度 + 安全）回归跑出来的真缺陷与修复
==========================================================
这一轮最值钱的东西不是新功能，是**回归脚本把三个"静默失效"的真缺陷挖出来了** ——
它们都不报错、界面上也"看着有反应"，只有把状态读回来对账才发现是死的。

缺陷 1（最严重）：原生推给控制台的消息一直是**字符串**，界面这边当对象用 → 整条推送链路静默失效
--------------------------------------------------------------------------------------------
· 现象：元素拾取器抓到元素后，控制台里「找元素」框**空的**、状态行还是"还没拾取过"；
  同理，打开控制台时的状态推送也进不去（p-url 之类只能靠别处补）。
· 根因：原生侧发的是
    console.evaluateJavascript("window.__cdpPush && window.__cdpPush(" + JSONObject.quote(o.toString()) + ")")
  `JSONObject.quote()` 把整段 JSON **变成一个 JS 字符串字面量**，所以 JS 收到的 o 是字符串，
  而 `__cdpPush` 里判断的是 `o.t === 'picked'` → 永远 false → 什么也不做；两边都不报错。
· 定位过程（值得记下来）：先手工用**对象**调 `__cdpPush` → 通了；再用**字符串**调 → 不通；
  最后把 /api/picker/last 的真 payload 灌进去，确认差异就在"传的是不是字符串"。
· 修复：界面入口统一加 `asObj(x)`（字符串先 JSON.parse，对象原样用），`__cdpPush` / `__cdpState` 都用它。
  修复后同一条链路：`picker/last` 抓到 `#divBtn` → `#q-sel` 真的变成 `#divBtn` → 提示文字变成"刚刚拾取：#divBtn"。
· 教训：**跨语言通道的"怎么传"要和"怎么收"对账**；这类错误不会抛异常，只能靠读回状态发现。

缺陷 2：替换嗅探栏目 HTML 时**连带吞掉了两个板块**（sniff-add / sniff-note）
--------------------------------------------------------------------------
· 现象：界面上少了"手动添加地址"和"说明"两块，三个键（sn-add / sn-go / sn-play）变成死键。
· 怎么发现的：**功能登记表自检**（本轮新做的）报了两条
    {"board":"sniff-add","problem":"登记了但 HTML 里没有这个板块"}
    {"board":"sniff-note","problem":"登记了但 HTML 里没有这个板块"}
  同时 `__cdpMissing()` 报出三个找不到的 id。补回 HTML 后归零。
· 教训：一块界面"在不在"必须能被机器问出来（登记表 + 差集），否则只能靠人肉翻 HTML。

缺陷 3：嗅探列表里的「下载」键调的是**不存在的 op 名**
----------------------------------------------------
· 现象：点了没反应，也不报错（旧代码写的是 `call('download', ...)`，Bridge 里的名字是 `download.start`）。
· 修复：改回 `download.start`；HLS 的走 `sniff.download`。

顺带修掉的两个"看着像网络坏了"的小坑
------------------------------------
· 用 App 自己的下载器去下**虚拟源地址**（appassets / cdp-event.local / cdp-meta.local）必然失败，
  日志里是 `UnknownHostException`。现在直接拦下来并回一句人话："这是 App 内部虚拟地址，外部下载器取不到，
  请用真实 http(s) 地址"。离线测试源改用控制口的 `/api/_test/audio/sample.mp3`（真 http、真字节）。
· 嗅探"清空"之后，**还在播的旧页面会重新登记**（实测），看起来像"清不掉"。现在每条带"来自哪个页面"，
  并加了「只看当前页」开关。

回归脚本自身的问题（也一并修了，避免下一轮再被假红误导）
--------------------------------------------------------
1. 断言写死了旧文案：嗅探栏目本轮把状态文字拆成 `sn-stats`（总览）与 `sn-out`（刚做了什么），
   脚本还在读旧的"共 N 条"；抽屉按钮文案带了功能数（"历史（1）"），断言还写 `== "历史"` → 都改成"包含"。
2. `#tabs button.on` 这种"平铺页签"的选择器在两級抽屉下已经不成立 → 改成 `#tabs button.tabBtn.on`，
   抽屉数量断言也改成"7 个集合 + 24 个栏目 + 登记表自检 problems 为空"。
3. `?tab=read` 这个栏目已经归到「自动化 ▸ 插件」→ 改成 `?tab=plugins`。
4. 探针选择：脚本里反复读界面状态时别用带"验活"的会话式探针（偶尔卡几十秒），
   新加了极简硬超时探针 `tools/uiprobe.mjs`；`cdp.mjs list` 这类命令在 shell 里一定要套 `timeout`。

环境事件（不是产品缺陷，但要如实记）
------------------------------------
· 本轮**模拟器崩了两次**（`docker ps -a` → `Exited (139)`，SIGSEGV），都发生在连续跑长套件的时候；
  表现是"某条断言莫名失败"或整组报"环境问题：模拟器不在线"。
  处理：重启模拟器 → 单独重跑受影响的组（`tools/split_suite.sh` 分段跑，就是为这个准备的）。
· 模拟器容器里的 DNS 对部分域名（archive.org）解析错误（解析到 `face:b00c` 段），
  宿主 curl 同地址正常 → 判定为容器网络问题；音频链路因此改成离线靶子来保证可复现。
