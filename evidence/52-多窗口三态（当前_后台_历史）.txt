多窗口三态（第 28 条 + 28.1：当前 / 后台 / 历史下来的，参考 Firefox）—— 实现与验收
=================================================================================
时间：2026-09-22   设备：模拟器 test35（Android 14 x86_64）
用户原话：「还有多窗口模式我之前说了要干嘛，什么表示在后台，什么表示当前，什么表示历史下来的，参考firefox」

【原来是什么样】▤ 菜单里每行只有「● 标题 ✕」（当前）/「○ 标题 ✕」（其余），
**没有**"被回收过（切回去要重载）"这一态，也**没有**"关掉的那个去哪了"（关了就没了，恢复不了）。

【现在（三态，按用户确认的口径）】
| 状态 | 含义 | 数据 | 菜单里长什么样 |
|---|---|---|---|
| 当前 | 正在显示 | `win.list` 里 `active=true` | 整行底色 + 「**●** 标题」，一行最多一个 |
| 后台 | 开着、状态还保活 | `kept=true` 且非 active | 「**○** 标题」，正常亮度 |
| 历史下来的 | ① 被回收过的（`kept=false`，切回去要重载） | `kept=false` | 标题**变暗** + 右侧「**⟳**」标记（content-desc「切回去要重新加载」） |
|  | ② 关掉过的（能恢复） | 新增 `closedWins`（持久化，最多 10） | 菜单底部一节「**最近关闭**」，每条「↺ 标题」，点一下恢复成窗口 |

实现要点：`winClose` 把关掉的那个 push 进 `closedWins`（标题空就退主机名）并落盘
（settings `winsClosedJson`）；新增 `win.recent` / `win.reopen` / `win.menu`（后者＝点 ▤ 那个动作，
也给验收与外部脚本"看一眼"）；启动时 `restoreClosedWins()` 一起恢复。

【验收 10 PASS / 0 FAIL】`python3 tools/verify_win_states.py`
  == 1. 当前/后台：开 3 个窗口 ==
    PASS 恰好一个窗口是 active（当前）：#2
    PASS 其余窗口都还在保活（kept=true，3 个）
    PASS 窗口菜单里：当前是实心 ●（1 个），后台是空心 ○（2 个）      ← dump 读的是菜单真实文本
  == 2. 开满 12 个 ==
    PASS 12 个窗口里 kept=true 的 10 个（上限 10 生效）
    PASS 被回收的窗口 kept=false：2 个（例：#0）
    PASS 被回收的行在菜单里带「⟳」标记（要重载）
  == 3. 关一个 → 进「最近关闭」 ==
    PASS 关掉一个：窗口 12→11，「最近关闭」10→10（满 10 条时挤掉最旧的一条）
    PASS 「最近关闭」里记着地址与标题
  == 4. 恢复它 → 变回窗口 ==
    PASS 点恢复：窗口 11→12，「最近关闭」10→9
  == 5. 重启 App ==
    PASS 重启后窗口 12 个、「最近关闭」9 条（和重启前一致）

  构件：apk/cdp-debug.apk（见 apk/apk-sha256.txt 最新一条）；接口文档重生成（含 win.recent/reopen/menu）

【排查记录（两个环境坑，别误判成产品）】
1. 第一次跑：菜单 dump 只读到 `<?xml…hierarchy`，看不到 ● / ○ / ⟳ ——
   真因是模拟器上弹了 **"Pixel Launcher isn't responding"** 的 ANR 窗（`text="Close app"/"Wait"`），
   dump 抓到的是那个窗。重启容器后同一个脚本 10/10。
   → 教训：dump 内容"看着像界面但不是我们的界面"时，先列出 dump 里的文本框看是不是系统弹窗/ANR。
2. 「最近关闭」满 10 条时再关一个，条数不变（挤掉最旧的一条）——这是**符合上限的正确行为**，
   第一版断言写"必定 +1"导致假红；判据改成 `min(旧+1, 10)`。
