小点（坐标步骤的落点）· 说明与证据
====================================
用户要的形态（照 clicker 项目那套）：
  · 坐标步骤在屏幕上画成**编号小点**；**元素步不画点**，但序号照占 → 页面上可能是 1 2 4；
  · 点一下小点 = "让它自己点那里"（回放这一步）；拖动小点 = 直接改这一步的坐标；
  · 同一个点连点几次 → 合成一个点（角标 ×N）；不同处的两个点可以合并成"一个点组"（仍然一步）；
  · 覆盖层走**无障碍**（`TYPE_ACCESSIBILITY_OVERLAY`），才能盖在视频/播放器上面。

怎么做
------
1. `CdpDotService`（无障碍服务）+ `DotBus`：把录制队列里的**坐标步**画成圆点，
   三态颜色跟 clicker 一致（待执行蓝 / 当前橙 / 已执行绿），角标 ×N 表示连点次数；
   轻点点 → 回放这一步；拖动 → 改这一步坐标（屏幕坐标回推成页面 CSS 坐标，再写回步骤）。
2. `res/xml/cdp_dots.xml`：`canRetrieveWindowContent="false"` —— **不读界面内容**，只画点、只收点的点击/拖动。
3. 页面里也画一份（`agent` 的 `dotsSet`）：没授权无障碍时的兜底 + 方便自动化验收读 DOM。
   两条路共用同一份数据（`Bridge.pushDots()` 一处生成）。
4. 回放期间覆盖层整层"不可触摸"（`FLAG_NOT_TOUCHABLE`）—— 否则注入的点击会打在点自己身上，
   页面收不到（这条是从 clicker 的开源实现里学到的关键点）。
5. 记录时**同一个点 1.5 秒内再点** → 合成一个点（`reps+1`，点上显示 ×N），不再产生多条。
6. 界面：录制栏目新增「①b 小点」板块（开关 / 去开无障碍权限 / 状态行）；
   步骤列表里每行标注**小点/元素**，小点行的小窗里多了「▶ 自己点这一下」「⇤ 和上一个点合并」。
7. 接口：`/api/record/dots?on=`、`/api/record/dots/status`、`/api/record/dots/play?n=`、
   `/api/record/dots/move?n=&x=&y=`、`/api/record/merge?index=`。

真手指端到端（用户那句"小点指向哪个坐标，然后让它自己点"）
----------------------------------------------------------
· 计算/暴露小点在**屏幕上**的位置（`/api/record/dots/status` 里的 `screen` 字段 + `/api/geom` 几何接口）
  → 真手指点它 → 日志：`小点：自己点第 1 步（坐标）` → `小点第 1 步：成功`，**恰好 1 次**，页面计数 = 1 ✓

过程中修掉的两个真缺陷（都是"会成环/会重复"的）
------------------------------------------------
① **回放注入的触摸会打到点自己身上 → 成环**：`accessibility` 覆盖层如果在回放期间"可触摸"，
   注入的触摸会被点自己吃掉（clicker 的 `FLAG_NOT_TOUCHABLE` 就是防这个）。
   我的 `busy` 只改了标志、**没重画窗口** → flags 不生效 → 实测一次点击变成 8 次连点。
   修法：`DotBus.setBusy()` 里改完标志**强制重画**。
② 修掉①之后还剩**页面里那份点**被注入触摸点到 → 同样成环。修法：回放期间把页面那份点也收起来
   （`pushDots` 里按 `!busy` 决定 `on`）。修完实测：一次真手指点击 = 恰好一次「自己点」。
