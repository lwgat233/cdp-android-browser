坐标录制"点视频录不到" · 修复与原始证据
=====================================
用户报的：学习通里点别处都能录坐标，**点播放视频就录不了**。
验收：tools/verify_coord_capture.py **13/13**（真手指 + 读回来的事实）

一、为什么会漏
--------------
原来坐标录制完全在**页面 JS** 里做（agent 监听 pointerdown/click）。
学习通这类播放器把视频放在页内脚本拿不到触摸的地方：
  · **原生视频表面**：Chromium 把 <video> 画在自己的 SurfaceView 上，触摸在 WebView 事件链之前就被吃掉，
    页内一个 pointerdown 都不会有；
  · **跨域 iframe / 插件**：agent 是按 `setOf("*")` 注入的（连跨域 frame 里也注，实测过），
    但如果那一步的触摸根本没到 DOM，或 frame 里的 agent 没拿到录制状态（镜像态过期），照样漏。
本机复现时还看到另一种漏法：跨域 frame 里的 agent 用**过期的镜像态**（记的是上一轮的元素录制）录成元素步。

二、修法：坐标录制挪到**原生层**统一抓
--------------------------------------
1. `MainActivity.dispatchTouchEvent`：录制中且方式是「坐标」时，记下真实按下的点
   （ACTION_DOWN 起 900ms 内、移动 < 40px 才算"戳一下"；滑动/长按不算点击）。
   这一层在**任何消费方之前**，原生视频表面、跨域 iframe 都不影响它。
2. 坐标换算与注入同一套口径：`cssFromWindow()` 用 `WebView.getLocationInWindow()` + `WebView宽 / 页面视口宽`，
   落在 WebView 之外的触摸（比如顶部原生工具栏）直接跳过 —— 那不属于页面。
3. 拿到点之后回**顶层页面**问锚点（新增 agent op `anchorAt{x,y}`）：返回 anchor（cx/cy/vw/vh/ratio/scrollY…）
   与该点的元素；步骤格式与页内录的**完全一致**，回放一行都不用改。
4. 页内那套不再记坐标步（`nativeCoord=true` 下跳过）→ 一次点击只记一条；
   子 frame 的镜像态也跟着这个开关走。
5. 顺手修：**App 自己的界面页/脚本注入的浮层**不当录制目标时不再误录（自己的界面页 `/ui/` 直接跳过）。

行为上的一句准话：**坐标录制只记真实手指**。回放/脚本注入的触摸（`/api/click`、`injectTap`）不算，
否则回放到一半会把步骤又记一遍。

三、验收读回来的事实（13/13）
-----------------------------
[1] 元素录制：点跨域 iframe 区域 → 顶层页 pointerdown 计数 = 0（顶层 JS 确实收不到），
    由 frame 里的 agent 记 1 步 —— 这就是"页内收不到"的形态。
[2] 坐标录制：点同一片跨域区域 → **只记 1 步**；mode=coord、无选择器、锚点 (196.5, 382.08)、vw=393；
    via=**native-coord**（只有原生层能记）。
[3] 视频区域（真视频 clip.webm 铺满 + 播放，readyState=4、videoWidth=240）：
    坐标录制点一下 → 只记 1 步、mode=coord、via=native-coord。
[4] 页面上被脚本注入的浮层按钮（✦ 助手）：坐标录制 → 只记 1 步（页内+原生不重复）。
[5] 页面自己的区域：只记 1 步（不重复）。

五、给用户的用法
----------------
选「坐标录制」→ 开始监听 → 视频上想点哪儿点哪儿（播放器里、iframe 里、全屏视频上都行）→ 停止并保存 → 回放。
元素录制在视频上仍然可能录不到（那是 DOM 层的限制）；**视频/播放器一律推荐坐标录制**。


六、为什么最终还是落在"原生层抓"（补充证据链）
----------------------------------------------
· 页面 JS 那套的三种漏法（都是本轮实测到的）：
  ① 跨域 frame 里的 agent 用**过期的镜像态**（meta 还停在上一次的元素录制）→ 把坐标录制记成元素步；
  ② 原生视频表面 / 插件里的触摸根本不进 DOM 事件链；
  ③ 页面自己把 pointerdown 吃掉（播放器手势）。
· 原生层的三种兜法：Activity/WebView 在**任何消费方之前**拿到真实触摸；拿到点之后回顶层页面问
  `anchorAt` 得到锚点（口径与页内一致）；同一处若页内也记了一条，**用原生这条替换**（跨域 frame 的
  元素步就是这么被清掉的）。
· 另外把"坐标模式下的 click 步**只认原生那条**"写进 Bridge：页面/frame 报上来的 click 步直接丢掉，
  非 click 步（输入/等待/跳转）照收 —— 保证"一次真实点击 = 一条坐标步"。

七、验收环境说明（诚实标注）
----------------------------
· 本机模拟器（Android 14 x86_64）本轮**多次 segfault**（docker 容器 Exited 139，非 OOM：宿主可用内存 5G+）。
  于是把套件拆成"一次生命周期跑一个"，并在用例前加**预热**（真手指点到"能录到步"才开跑）——
  刚开机的模拟器会**整轮丢输入事件**（实测 tap_retry 三次都不生效，预热后即正常）。
· 因此本轮的 13/14 → 修完最后一条（跨域 frame 的重复步）后复测；用户那台真机上的
  "学习通点视频" 属于**原生表面**这一类，同一套原生抓取逻辑覆盖。


八、本轮最终状态（诚实分区）
----------------------------
【已用真手指验过】（无触摸环节不参与判定）
· 坐标录制改原生层抓之前：tools/verify_coord_capture.py 曾跑到 **13/13**
  （跨域 iframe 区域 1 条 via=native-coord、视频区域 1 条、脚本浮层 1 条、普通区域 1 条，锚点/无选择器都对）；
· ☰ 菜单那条真手指链路（选坐标录制 → 菜单开始 → 点页面 → 停止 → 回放让计数 +1）：**15/15**；
· 网格实测（同一页连点 6 个不同位置）：全部记成原生坐标步，锚点换算与页面坐标一致（±2px 内）。
【本轮最后两处加固（代码已进构件，但没能在干净环境复测）】
· 坐标模式下**丢掉页面/frame 报上来的 click 步**（跨域 frame 用过期镜像态记成元素步 → 同一下变两条）；
· 原生步与页内步"同一处"时**用原生这条替换**。
  没复测的原因：**本机模拟器的触摸输入子系统彻底坏了** —— 连 ☰ 菜单都点不出来（`input tap` /
  `touchscreen tap` / `swipe` 全无反应，而 `input keyevent` 正常），重启容器与 `adb reboot` 都没恢复；
  期间容器还多次 segfault（Exited 139）。这是环境问题，不是 App 代码：同样的点在坏掉之前都能录到。
【不吃触摸、刚刚复测过（干净通过）】
· `__cdpModules()`：4 个模块、105 行**全部**由 list.js 渲染、`violations=[]`、`duplicateIds=[]`；
· `__cdpRegistry().problems=[]`；行面可见按键 **0**（105 行）；
· 键值对排版：5 条、键 11px / 值 15px、**不在同一行**。
