B-84 卡顿：cookie 读取按域名做重活（我上一轮改出来的回归）
=========================================================
时间：2026-09-22    设备：模拟器 test35（Android 14 x86_64）
用户原话：「打开应用和首页会卡顿，可能是与APP加载不出来有关，cookie打开也有困难，卡顿」

【怎么量的（A/B，同一台设备、同一份数据）】
造出真实规模：往书签里塞 20 个不同域名（site1.example … site20.example，经控制台页面
`CDPT.call('bookmark.add',…)`），加上原有 1 个 → 21 个域名。
（`/api/status`… `cookiesAll()` 会扫 当前页 + 历史 + 书签 的域名，对**每个域名**调一次 cookie 读取）

  构件                                      /api/cookies 耗时
  ─────────────────────────────────────────────────────────────
  旧构件（我改动之前）                       0.30s / 0.33s / 0.34s
  回归版（B-82 修复后）                      **17.08s / 16.94s**
  修好后（本轮）                             0.03s（热）/ 0.06–0.07s（清空后立刻读）

【真因（两层）】
1. `cookiesAll()` 对**每个域名**调一次 `cookiesFor(d)`；每个域名内部又 `merge()` → 读一遍 cookie 库
   （复制 + 打开 SQLite），这是**改动前就存在**的按域名成本（21 域名 ≈ 0.3s，可忍）。
2. 我 B-82 加的 `flush()` 与"一条对不上就等 200ms×3"是**写在按域名的那一层里的**：
   21 个域名里 20 个没有 cookie → 20 × (flush + 600ms 空等) ≈ 17s。
3. 这活跑在 **UI 线程**上：`HttpControl.call()` 是 `act.runOnUiThread { dispatch }`，
   `cookie.all` 同步执行 → 17 秒里界面完全停摆：控制台打不开、Cookie 栏目打不开、
   首页小 app 的请求也排在同一个 UI 线程队列后面（用户说的"打开应用和首页卡顿"）。
   另外控制台会记住上次栏目（localStorage `cdp.tab`），上次停在 Cookie 就**每次启动**都触发这一炮。

【改法（不再按域名做贵操作）】
· `CookieDb` 改成**一次快照**：`snapshot(force)`，TTL 3 秒内复用；`flush()`、复制库、SQLite 查询
  只在真正刷新时发生一次（原来每域名一次）。整库为空才等一拍（2 × 150ms），只在刷新时发生。
· `merge(list, attrs)`：把快照当参数传进来，一次请求共用一份。
· `cookiesAll()`：域名来源改成**库里真有 cookie 的站点**（`CookieDb.hosts()`）＋当前页域名，
  不再扫"历史 + 书签里的所有域名"（没有 cookie 的域名纯属白问）；域名数上限 300。
· 保住"刚写入不等也能看到属性"这条判据：只有**当前页**确实有 cookie 而快照里一条都对不上时，
  才等 200ms 再读一次（整轮一次，不是每域名一次）。

【验收】
1) 属性判据不退化：`python3 tools/verify_cookie_attrs.py` → **10 PASS / 0 FAIL**
   （API 面 5：hocookie httpOnly=True、真过期时间 2026-09-23 02:40:13、expiresMs、会话期如实显示；
     界面面 5：真手指点 (206,251)，小窗读到真过期时间/HttpOnly=是/有效期 1 天、写死文案已删）
2) 卡顿消除：/api/cookies 17.0s → **0.03s**；打开 Cookie 栏目接口 0.02s。
3) 构件：apk/cdp-debug.apk  42033401 字节
   sha256 686d128a2f0128f17dd4c7a5c87fae52b2f1f7a810bfc36604bf57d02daf1790
   构建：gradle --no-daemon --offline :app:assembleDebug → EXIT=0（1m12s）

【教训（已写进 android 技能 webview-ui-pitfalls.md）】
"一次请求只读一次贵东西"必须落在**调用方**（一次快照 + 共用），别落在被循环调用的小函数里；
这些 op 全在 UI 线程上跑，按域名叠加的毫秒会变成整界面的秒。
