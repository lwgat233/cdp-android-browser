本轮最重的一个 bug：**信息行小窗里的动作键全是死的**（用户报的"小窗里面的按键都没用"）
────────────────────────────────────────────────────────────────────
现象（用户原话）："下载里面的小窗口按键也没用" / "m8u8 点击小窗口，播放按键没效果" / "需要重复实验一下按键问题，对于小窗口内的东西"。

真因（一次探针把事实全读出来才定位到）：
  · `modules/list.js` 给信息行生成的动作是 `{t, danger, fn}`；
  · `modules/modal.js` 渲染动作栏时**只认** `{label, run}` 和 `{op, args}`；
  · 于是动作键渲染出来了、文案也对，但 `a.run`/`a.op` 都是 undefined → 点击**只把窗关掉，什么都不做**。
  · 影响面：**所有信息行小窗的动作**（下载/播放/投屏/打开/删除/导出/复制…）全都点不动。
修法：
  · `modal.js` 三种写法都认：`run`（正式）/ `fn`（list.js 旧写法）/ `op`（直接给 op 名）；
  · `list.js` 同时给 `label + run`（正式写法）与 `t + fn`（兼容），并且把这条规矩写在注释里。
验收（真手指点 + op 日志）：点「▶ 播放」→ **真的打开内置播放器**（`/api/status.browser.url` 含 `player.html`），
`/api/player/state` 有 `hasVideo=true`；点「投屏」→ 有可读回执（"已在搜索设备，搜到会弹出选择框"），不再静默。
顺带修的（同一条链上）：
  · 「投屏」原来调 `cast.play` 但**没带设备** → 后端只认"先搜设备"的 `cast.open` → 静默失败；已改走 `cast.open`。
  · 「▶ 播放」确实打开了播放器，但**控制台浮层还盖着** → 用户看到的还是控制台（"没效果"）。
    新增 `backToPage()`：会把人带离控制台的动作（播放 / 打开）**点完自动收起控制台**（用户第 3 条要求）。

补记（同一夜的第二层修复与最终验收事实）
────────────────────────────────────────────────────────────────────
**第一版修完还是不稳**：定向探针显示"点确实落在按键上（hitSelf=true）、面板可见（z-index 99 正常），
但点下去没有任何 op 被调用"。说明问题不在"点不到"，而在**点击的转发链**：
list.js 把行里的按键从 DOM 里**搬走**（`b.remove()`），只交给小窗一个"点它会转发"的闭包 → 这层代理在小窗里会静默失效。

**彻底修法**：小窗里**直接摆那个真按键元素**（list.js 传 `el: b`，modal.js 优先用它；同时不再传 run/fn，
避免重复执行），小窗只负责"点完把自己收起"。这样点击就是一次正常的 DOM 点击，中间没有可失效的一层。
验证（定向探针 `/vol1/1000/airesults/cdp/source/cdp/tools/probe_sheet_click.py`）：
  · 目标按钮 = `BUTTON.mini2`，`hitSelf: true`（真元素就在小窗里）
  · 点它 → op 日志出现 **`player.open` + `ui.close`** → 当前页变成 `player.html?u=…`  ✔
  · 批测里同样通过：`点「▶ 播放」→ 页面真的变成内置播放器` **PASS**、`内置播放器读得到状态（有 video）` **PASS**
