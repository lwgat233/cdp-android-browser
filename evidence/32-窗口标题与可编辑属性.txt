一、你先问的两件事：实测结果（不是猜的）
════════════════════════════════════════════════════════════════════

【1】「按键功能在后台可能会失效，对吧？」→ **这台设备+这个版本：不失效，实测点得动。**

  做法：测试页（assets/test/tap.html）整屏可点、点一次计数器 +1，并且记录事件是不是"真事件"（isTrusted）。
    · 前台跑一次：计数 0 → 1，isTrusted=true
    · 按 HOME 切后台再跑：计数 1 → 2，isTrusted=true      ← 后台照样点得动
    · **熄屏**（KEYCODE_POWER，mWakefulness=Asleep）再跑：计数 2 → 3，isTrusted=true
  同时后台状态下 /api/status、/api/eval、/api/replay 都正常回包。

  仍然会失效的情形（如实说）：
    · 系统进入 Doze/省电（长时间熄屏且静止）会限制网络 → 网络类步骤会失败；
    · 内存吃紧时 WebView 被系统回收 → 会失败；
    · 我们自己的实现不会主动 pause WebView（这点是对的，后台播放也依赖它）。

【2】「流量计算看起来有问题」→ 查清了：**没有假数字，但名不副实，容易被误解。**
  · 现在统计的是 `total`＝**请求条数**（697 条就是这么来的），另有 blocked / media；
  · 上/下行字节 `bytesDown/bytesUp` **只统计应用自己搬运的**（下载、m3u8 分片、代理中继），
    页面内的流量 WebView 不暴露给应用 —— 所以平时显示 `0 B`，注释里写着"拿不到就不编"；
  · 界面文案是「被拦截 N　应用自搬运 下 X / 上 Y」。
  → 问题在于"流量"这个词让人以为是在算网页流量。改法已给你选项（见最后）。

二、多窗口：按页面标题命名 + 只在那个图标里管
════════════════════════════════════════════════════════════════════

改之前：工具栏下面有一条「窗口 1 ✕ 窗口 2 ✕ ＋」的窗口栏；窗口菜单里一律叫「窗口 N」；
        控制台里还有一个整栏「窗口」（列表 + 刷新/新建/关闭三个键）。

改之后：
  · **工具栏下面那条窗口栏删掉了**（重建窗口栏的函数留成空壳，调用处不用改，只刷新图标指示）。
  · 窗口名字＝**页面标题**：页面加载完就把标题记到当前窗口上（`wins[activeWin].title = lastTitle`），
    菜单项、`/api/win` 接口都显示标题（当前窗口直接取实时标题，不拿缓存）。
    标题空 → 退回主机名 → 退回地址尾部 → 才叫"新窗口"。**不再有「窗口 1」这种名字**。
  · 工具栏指示：只有一个窗口时就是「▤」，多窗口时「▤N」（名字在弹出来的列表里看）。
  · 新建 / 切换 / 关闭 **只**在地址栏后面那个「▤」图标里（用户说的"搜索栏后面那个图标"）。
  · **控制台里的「窗口」整栏删除**：index.html 的 section、registry.js 的集合与功能条目、
    app.js 的 loadWins/winFloat/三个按键绑定、test_map.json 的 win.list 全清掉。
    原生 win.new / win.close / win.switch / win.list 都还在（那个图标用的就是它们）。

验收（tools/verify_edit_and_layout.py [1][2]）：
  · 控制台里没有 #tab-win；登记表 problems=[]（删干净，没有"登记了没做"）
  · `win.list` 里当前窗口的标题 = 「点我测试页」（真读回来的）
  · **真手指**点工具栏「▤」→ uiautomator dump 出来的菜单里有「点我测试页」，
    还有「＋ 新窗口」「✕ 关掉当前窗口」，而且 dump 里**没有**「窗口 1」

四、属性可编辑（历史 / 书签 / Cookie），Cookie 还能添加
════════════════════════════════════════════════════════════════════

原生新接口（同一套 op 也给外部用）：
  · `cookie.set`            → `/api/cookie/set?domain=&name=&value=&path=&maxAge=&secure=&httpOnly=`
      走 CookieManager.setCookie，写完**读回来确认**；没写进去就如实说原因（域/路径对不上等）。
  · `bookmark.update`       → `/api/bookmark/update?id=&title=&url=&folder=`（只改传进来的项）
  · `history.update`        → `/api/history/update?ts=&url=&title=`（历史没有 id，按 ts+url 定位）

界面（都用小窗那套形态：**键在上、值就是文本框**，底部〔恢复原始值〕〔确定〕）：
  · 历史行点开 → 标题可改；地址/站点/访问时间只读；附加键「在浏览器里打开」。
  · 书签行点开 → 标题/地址/文件夹可改；附加键「✕ 删掉这条书签」；行里不再摆按键。
  · Cookie 行点开 → 值/路径/有效期/Secure/HttpOnly 可改（名字与域是身份，只读）；附加键「✕ 删掉」。
  · Cookie 列表**最底部**加了「＋ 添加 cookie」一行（形态与步骤列表底部那个加号一致），
    默认域＝当前页面的站点（读一次状态，不是猜的）。

验收：
  · 历史：点行 → 小窗 4 个文本框 + 〔恢复原始值〕〔确定〕；标题改成「改过的标题-验收」→ `/api/history` 读回新标题 ✓
  · 书签：小窗里 title/url/folder 都是可改（readonly=0）✓
  · Cookie 新增：走界面填 域/名字/值/有效期 → `/api/cookie/detail` 读回 v1 ✓
  · Cookie 改值：走界面改 v2 → 读回 v2 ✓（孤立复现日志：`已更新 cdp_z @ example.com`）

  ⚠ 验收脚本已知的时序假红（脚本问题，不是产品）：控制台切栏目会重载页面、行与模态被重建，
    [5] 书签小窗 / [7] cookie 改值在"整套连跑"时会假红；按同样步骤单独复现稳定通过。
    已在脚本头部写明，不当作 28/28。
