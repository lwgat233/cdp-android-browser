二、实测发现的 5 个问题（P1/P3/P4/P5 已修，P2 是既有能力、已卡住防回归）
════════════════════════════════════════════════════════════════════

P1 **页面里的 `<video>` 是空的（真播放器在跨域 iframe 里）**，于是"看视频状态 / 查播完了吗 /
   交给系统播放器"在这个站什么都读不到；而界面只说"没识别到 video"，不告诉你去哪看。
   → 改：那句提示补成「这一页没识别到 <video>/<audio>（播放器可能在跨域 iframe 里）→ 看「嗅探」抓到的流」。

P2 **嗅探本身是好的**（这次要保住的既有能力）：真链被抓住了（host=v.baofeng9.com，不是 iframe 那层），
   条目里记着「来自哪个页面」；**分片合并成一条**（`segs` 从 43 → 62 随播放增长），不是几百行刷屏。
   → 已写成回归断言（免得以后又被"分片刷屏/抓不到"之类改坏）。

P3 **内部通道混进了清单与网络时间线**：`https://cdp-meta.local/meta?k=…`（我们自己的页面→原生日志通道）
   与本机控制口轮询都出现在"请求时间线"里 —— 噪声，会把真实请求淹掉。
   → 改：`isInternalUrl()`，`appassets.androidplatform.net` / `cdp-event.local` / `cdp-meta.local` /
     `127.0.0.1:` / `localhost:` 一律不进嗅探、不进时间线（页面照常拿得到这些资源）。

P4 **「用内置播放器打开」之后读不到播放器状态**：接口只有 `player.open`，没有"读"这一半，
   控制台上显示空，看着像没播。
   → 改：新增 op `player.state` + 路由 `/api/player/state`（`/api/player` 不带 url 时也走它）：
     返回 `{playerPage, url, hasVideo, paused, ms, durMs, ready, err}`；
     嗅探板块加一键「看播放器状态」。实测：`{"playerPage":true,"hasVideo":true,"paused":false,"ms":1958,"durMs":1938800}`

P5 **m3u8 下载期间看不出在动**：记录里 `bytes` 一直是 0、没有分片进度（只有日志里有 N/M）。
   → 改：`HlsDownloader.download(..., onProgress)`，每 10 片把 `segsDone / segsTotal / bytes / state`
     写回下载记录；下载行显示 `名称 12.3 MB 100/1999 片 进行中 100/1999 片`。
     实测：`{"state":"进行中 10/1999 片","bytes":3790832,"segsDone":10,"segsTotal":1999}`

（顺手做的）功能规格-逐板块 里补了这些口径。

三、验收（判据都是读回来的事实）
════════════════════════════════════════════════════════════════════

两套脚本，分开跑（原因见下）：
  $ python3 tools/verify_sniff_yhtn.py        → 15/17（15 条绿；起播/真链/合并/过滤 全绿）
  $ python3 tools/verify_sniff_player_dl.py   → **6/6**（播放器状态 + 下载进度，专门单跑这一套）

为什么分两套：整套跑要"开页面 → iframe 起播 → 内置播放器播放 → 下载 1999 个分片"，
这个负载下 **模拟器容器会 segfault**（本轮实测死了两次，`notifbridge-emu` 直接消失）
→ 后面那两条读到的都是空，看着像产品坏了，其实是环境。现在把这两条单独成一套、跑完立刻
`force-stop` 停掉下载线程并清掉下载目录，结果才可信、也不会把模拟器压崩。

verify_sniff_yhtn（真实站点）读出的事实：
  · 抓到 m3u8：`https://v.baofeng9.com/video/moxuMAO/2c8deaadbc1d/index.m3u8`，host=v.baofeng9.com
  · 条目带来源页：`https://yhtn.cc/p/1374711/229/0`
  · 分片：1 条合并条目，segs 42→62 增长（不是刷屏）
  · 内部地址：cdp-meta.local / appassets / 127.0.0.1:8848 **都不在**清单与时间线里（而真实请求有 50 条）

verify_sniff_player_dl 读出的事实：
  · player.state = {"playerPage":true,"hasVideo":true,"paused":false,"ms":1958,"durMs":1938800}
  · 下载记录 = {"state":"进行中 10/1999 片","bytes":3790832,"segsDone":10,"segsTotal":1999}
