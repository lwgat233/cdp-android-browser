网络统计（字节）：上行恒 0 的修复 + 没挂代理时的如实标注
=========================================================
时间：2026-09-22   设备：模拟器 test35（Android 14 x86_64）
用户原话：「继续，网络统计问题等等的」（没指明具体哪种，所以先量化再改）

【先量化，找出真问题】
  基线（默认：proxyType=none、selfProxy=0，即直连）：
      /api/net/stats?range=day → proxyDown=0  proxyUp=0  todayDown=0
      直连加载一个已知资源后仍是 0 —— 不是"没数据"，是**这个口径下根本不会数**。
  打开自代理后再加载同一个资源：
      proxyDown=15920（3 次加载 × 3980）而 **proxyUp 一直是 0**。
      → 下行在数、上行恒 0：这是真 bug。

【真因 1：上行恒 0（已修）】
  `ProxyRelay` 的两条转发路径里，**请求头都是直接写出去的、没进计数器**：
    · 明文 HTTP：`uo.write(outLines…)` 写请求头 → 之后才 `upBytes` 计数（只数 body）
    · CONNECT 隧道：客户端那条 head 被 `readHead()` 读走 → 也只数隧道里的 body
  修：把请求头字节作为上行初值（HTTP 路径用实际写出的 `headSent.size`；CONNECT 路径用 `head.length`），
      并把上行那条 pipe 的 `join(500)` 放宽到 800ms（keep-alive 时计数还没读完就被读走了）。
  实测：明文 HTTP 上行 **2116 字节**、CONNECT 隧道上行 **1590 字节**（修之前都是 0）。

【真因 2：口径限制，改成如实标注（已修）】
  字节只能数"应用自己中继搬运过的"（页面内流量 WebView 不暴露给应用）。默认直连 → 统计恒 0，
  而界面上只写"应用自搬运字节 下 0 B / 上 0 B"，用户看着就是"没数/不对"。
  修：`net.list` 回包带 `relay` 与 `proxyPort`；网络面板那行按状态如实标：
      · 没开代理且没历史字节 → 「（没开代理·无字节）」
      · 没开代理但有历史字节 → 「（当前没开代理）」
      · 开着 → 不标，正常显示数字
