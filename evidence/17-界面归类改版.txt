    结果：{"ok":true,"collections":7,"tabs":24,"features":45,"boards":45,
           "byColl":[{"key":"browse","tabs":3,"features":6},{"key":"auto","tabs":4,"features":10},
                     {"key":"privacy","tabs":4,"features":5},{"key":"media","tabs":3,"features":7},

    ★ 自检真的抓到过一次缺陷（这就是它存在的意义）：
      在把三块 Cookie 合并成一块、把广告拦截与屏蔽名单合并成一份规则库的过程中，
      替换 sniff 栏目 HTML 时连带吞掉了 sniff-add / sniff-note 两个板块，界面上少了两块、三个键变成死键。
      自检报了两条：{"board":"sniff-add","problem":"登记了但 HTML 里没有这个板块"}、
                      {"board":"sniff-note","problem":"登记了但 HTML 里没有这个板块"}
      另有 __cdpMissing() 报出 sn-add / sn-go / sn-play 三个 id 在页面上找不到。补回 HTML 后归零。

五、后端合并（一份规则库）在两条通道上都验过
    ① 应用内 op（控制台走的那套）：
       adblock.warn.add {host:probe.example.com} → ok=true
       adblock.get → warn 列表里能看到这条（rules=43）
       security.block.list（老 op）→ 同一份数据里也能看到 → 老接口没被破坏
       adblock.warn.remove → ok=true
    ② HTTP 控制口（电脑侧 curl，另一条通道）：
       GET /api/adblock/warn/add?host=http-probe.example.com → {"ok":true}
       GET /api/adblock            → warn=['http-probe.example.com']  rules=43
       GET /api/security/block     → {"ok":true,"list":["http-probe.example.com"]}
       GET /api/adblock/warn/remove?host=… → {"ok":true}
    ③ 迁移：老的 settings 里那条逗号串（blockHosts）在启动时一次性并进规则库并清空原键，
       命中判断全部改走 AdBlock.matchWarn()（警告条与页面安全结论共用同一个匹配器）。
